The lightbox provider owns the active photo, navigation order, zoom state, transitions, gestures, and modal lifecycle. Recipe components create that provider for the common paths.

::lightbox-behavior-lab
::

## Recipes decide who owns the viewer

`PhotoAlbum` creates a lightbox by default. `PhotoGroup` creates one provider for all participating descendants. A standalone `Photo` and `PhotoCarousel` create one only when their `lightbox` prop enables it.

When a recipe is inside an enabled `PhotoGroup`, the group owns the viewer. The descendant contributes its trigger and optional slide renderer instead of creating another provider.

## Transition modes describe the opening source

Set `transition` on the component that owns the provider.

| Mode   | Behavior                                                                     |
| ------ | ---------------------------------------------------------------------------- |
| `auto` | Uses FLIP when the source thumbnail is sufficiently visible, otherwise fades |
| `flip` | Requests the thumbnail frame and falls back when its geometry is unavailable |
| `fade` | Cross-fades without moving from the thumbnail frame                          |
| `none` | Opens and closes without a transition                                        |

`auto` is the default. It avoids animating from a thumbnail that is mostly outside the viewport or too small to provide a useful source frame. Closing also falls back to a fade when the original thumbnail has unmounted or moved out of view.

```vue [app/pages/gallery.vue]
<PhotoAlbum :photos="photos" :transition="{ mode: 'auto', autoThreshold: 0.6 }" />
```

The operating system reduced-motion preference changes `auto` and `flip` to a fade. Explicit `none` remains instant.

## Input follows the current zoom state

The built-in viewer supports these interactions:

- Arrow keys move between photos, or pan a zoomed image horizontally.
- `Escape` closes the viewer.
- `Z`, double click, or double tap toggles zoom.
- The mouse wheel changes zoom.
- A horizontal drag changes slides when the image is fitted.
- A drag pans a zoomed image; an outward horizontal drag at its edge can change slides.
- A two-pointer gesture pinches to zoom.
- A vertical drag closes a fitted image.
- A single tap toggles the viewer controls.

Navigation commands are ignored while the viewer is closed or a conflicting transition is active. The [programmatic control guide]($docs/guides/programmatic-lightbox) uses the same controller contract as these built-in inputs.

## The viewer owns modal focus

The recipe `Lightbox` renders a dialog in `body`. While open, it:

- locks body scrolling;
- moves focus into the dialog;
- keeps Tab focus inside its controls;
- marks page siblings inert and hidden from assistive technology;
- restores focus to the opening element after close when that element still exists.

Only one Nuxt Photo provider can own that modal state. Opening a second viewer first closes the active one, then transfers ownership.

## Collection updates preserve identity

If a collection changes while the viewer is open, Nuxt Photo follows the active photo by `id`. Reordering the collection updates its index without changing the visible photo. Removing the active ID closes the viewer because there is no longer a valid slide to own.

## Provider options are setup-time

`lightbox`, `transition`, and `imageAdapter` determine the provider created during component setup. Remount the owner with a new `key` when one of those capabilities must change at runtime.

```vue [app/components/SwitchableGallery.vue]
<PhotoAlbum :key="transitionMode" :photos="photos" :transition="transitionMode" />
```

Reactive photo data can change without a remount because identity is reconciled separately from provider configuration.
