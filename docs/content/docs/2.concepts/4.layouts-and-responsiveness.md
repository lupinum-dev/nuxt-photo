title: Layouts and responsiveness

`PhotoAlbum` lays out the same photo collection as justified rows, balanced columns, or masonry. All three use intrinsic dimensions and the width of the album container.

::album-layout-lab
::

## Choose a layout by reading behavior

| Layout    | Placement                                                    | Primary setting   |
| --------- | ------------------------------------------------------------ | ----------------- |
| `rows`    | Groups photos into justified horizontal rows                 | `targetRowHeight` |
| `columns` | Preserves sequence while balancing sequential columns        | `columns`         |
| `masonry` | Places each photo in the current shortest equal-width column | `columns`         |

Rows are the default. Pass the short name when the defaults are enough, or use the object form to configure the selected layout.

```vue [app/pages/gallery.vue]
<template>
  <PhotoAlbum :photos="photos" :layout="{ type: 'rows', targetRowHeight: 240 }" :spacing="8" />
</template>
```

Columns and masonry use the same `columns` setting but produce different visual order and height distribution.

```vue [app/pages/gallery.vue]
<PhotoAlbum :photos="photos" :layout="{ type: 'masonry', columns: 3 }" />
```

## Resolve settings from the container

`spacing`, `padding`, `targetRowHeight`, and `columns` accept a static number or a function of the measured container width. The `responsive()` helper creates a mobile-first resolver from a breakpoint map.

::responsive-lab
::

```vue [app/pages/gallery.vue]
<template>
  <PhotoAlbum
    :photos="photos"
    :layout="{
      type: 'columns',
      columns: responsive({ 0: 2, 640: 3, 960: 4 }),
    }"
    :spacing="responsive({ 0: 4, 640: 8, 960: 12 })"
  />
</template>
```

Breakpoint keys are minimum container widths in pixels. At 760px, the example resolves to three columns and 8px spacing regardless of the browser viewport.

The Nuxt module auto-imports `responsive()` by default. Use an explicit import when auto-imports are disabled.

```ts [app/utils/gallery-layout.ts]
import { responsive } from '@nuxt-photo/nuxt/app'

export const gallerySpacing = responsive({
  0: 4,
  640: 8,
  960: 12,
})
```

## Breakpoints also stabilize measurement

`responsive()` attaches its positive breakpoint keys to the resolver. `PhotoAlbum` merges those keys from its responsive settings and snaps the measured width down to the largest matching breakpoint.

You can pass `breakpoints` explicitly when the layout should snap at widths that are not present in a resolver.

```vue [app/pages/gallery.vue]
<PhotoAlbum
  :photos="photos"
  :breakpoints="[640, 960, 1280]"
  :layout="{ type: 'columns', columns: responsive({ 0: 2, 640: 3, 960: 4 }) }"
/>
```

Snapping limits layout recalculation between meaningful widths and gives the server and client values they can share. The [server rendering concept]($docs/concepts/server-rendering) explains how to choose the initial width.

## Change layout type explicitly

Responsive parameters configure numbers, not the `layout.type` discriminant. Use reactive application state when the layout itself must change.

```vue [app/pages/gallery.vue]
<PhotoAlbum
  :photos="photos"
  :layout="isCompact ? { type: 'masonry', columns: 2 } : { type: 'rows', targetRowHeight: 260 }"
/>
```

Prefer one layout across widths when possible. It preserves a more consistent reading order and reduces visual movement when the container crosses a breakpoint.
