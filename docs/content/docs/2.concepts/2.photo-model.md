---
title: Photo model
description: Give every photo stable identity, intrinsic dimensions, and optional presentation data.
---

Every Nuxt Photo component consumes `PhotoItem`. Normalize CMS records, API responses, and local assets to this shape before rendering them.

```ts [app/data/photos.ts]
import type { PhotoItem } from '@nuxt-photo/nuxt/app'

export const photos: PhotoItem[] = [
  {
    id: 'alpine-lake',
    src: '/photos/alpine-lake.jpg',
    thumbSrc: '/photos/alpine-lake-thumb.jpg',
    width: 1600,
    height: 1000,
    alt: 'An alpine lake below a rocky ridge',
    caption: 'Alpine lake',
  },
]
```

## Required fields

| Field    | Requirement                                | Why it matters                                               |
| -------- | ------------------------------------------ | ------------------------------------------------------------ |
| `id`     | Non-empty string, unique in the collection | Preserves active-photo identity and trigger registration     |
| `src`    | Non-empty string                           | Supplies the full image source                               |
| `width`  | Positive finite number                     | Reserves the correct aspect ratio and drives layout geometry |
| `height` | Positive finite number                     | Reserves the correct aspect ratio and drives layout geometry |

Use intrinsic pixel dimensions, not the rendered CSS size. Incorrect dimensions produce incorrect album geometry and an inaccurate opening frame even when the browser can still load the image.

Use an asset or CMS identifier for `id`. Array indexes change when a list is filtered or reordered and therefore cannot preserve identity reliably.

## Optional fields

| Field         | Behavior                                                                        |
| ------------- | ------------------------------------------------------------------------------- |
| `alt`         | Becomes the image alternative text; an omitted value renders as an empty string |
| `caption`     | Appears in the `Photo` figure and the default lightbox                          |
| `description` | Adds longer text to the default lightbox caption                                |
| `thumbSrc`    | Replaces `src` for thumbnails in the native image path                          |
| `srcset`      | Passes explicit candidates to the native image path                             |
| `meta`        | Carries application-owned data into slots and adapters                          |

Keep `meta` for presentation data that Nuxt Photo does not interpret, such as a photographer, credit URL, or media kind.

```ts [app/data/photos.ts]
type PhotoMeta = {
  photographer: string
  creditUrl: string
}

export const photos: PhotoItem<PhotoMeta>[] = [
  {
    id: 'alpine-lake',
    src: '/photos/alpine-lake.jpg',
    width: 1600,
    height: 1000,
    meta: {
      photographer: 'Ada Example',
      creditUrl: 'https://example.com/ada',
    },
  },
]
```

## Validation fails at the rendering boundary

`Photo` and `PhotoGroup` reject invalid data. `PhotoAlbum` and `PhotoCarousel` also default to `validation="throw"`, which raises a `PhotoValidationError` before layout calculation.

Use `validation="drop"` only when omitting invalid entries is an intentional product decision. Handle the `invalidPhotos` event so a broken CMS response remains visible. The event is client-only and runs after rendering; report server-side ingestion failures at the data boundary instead.

```vue [app/pages/gallery.vue]
<script setup lang="ts">
import type { InvalidPhotosEvent } from '@nuxt-photo/nuxt/app'

function reportInvalidPhotos(event: InvalidPhotosEvent) {
  console.error('Invalid photo collection', event.issues)
}
</script>

<template>
  <PhotoAlbum :photos="photos" validation="drop" @invalid-photos="reportInvalidPhotos" />
</template>
```

Map external records once at the application boundary. The [CMS gallery guide]($docs/guides/cms-gallery) keeps source-specific fields out of component templates.
