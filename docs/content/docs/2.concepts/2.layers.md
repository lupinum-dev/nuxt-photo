Nuxt Photo has a few supported entry points. They are ordered by how much UI you own.

```text
<PhotoAlbum> / <Photo> / <PhotoCarousel>  Ready-made gallery pieces
<PhotoGroup>                              Shared lightbox across photos/albums
<PhotoGroup v-slot>                       Custom layout, default lightbox
Primitives + composables                  Custom lightbox structure
```

## Recipe components

Use recipe components first. They cover the common cases: a single photo, an album, a grouped set of albums, or a carousel.

```vue
<PhotoAlbum :photos="photos" layout="rows" />
```

Rows render responsively on the server without a fixed width. Columns and masonry need `defaultContainerWidth` for deterministic server-rendered groups; otherwise SSR uses a simple grid fallback and the grouped layout recomputes after mount.

Use recipes when:

- You want a gallery without owning lightbox internals.
- Rows, columns, masonry, or carousel match the design.
- CSS variables, classes, and slots are enough customization.

## Grouping and custom layouts

Use `<PhotoGroup>` when several photos or albums should share one lightbox and one next/previous flow.

```vue
<PhotoGroup>
  <PhotoAlbum :photos="landscapes" layout="rows" />
  <PhotoAlbum :photos="studies" layout="columns" />
</PhotoGroup>
```

Use `<PhotoGroup v-slot>` when the built-in layout is wrong but the default lightbox is still right.

```vue
<PhotoGroup :photos="photos" v-slot="{ trigger, photos }">
  <figure
    v-for="(photo, i) in photos"
    :key="photo.id"
    v-bind="trigger(photo, i)"
  >
    <img :src="photo.thumbSrc ?? photo.src" :alt="photo.alt" />
  </figure>
</PhotoGroup>
```

## Custom lightboxes

Use primitives and `useLightboxProvider()` when you need a different lightbox structure. The primitives provide context wiring, focus handling, viewport bindings, controls, captions, slide rendering, and the ghost image used by FLIP transitions. You still own the markup, classes, and final accessibility review for your composition.

```vue
<LightboxProvider :photos="photos">
  <PhotoTrigger
    v-for="(photo, i) in photos"
    :key="photo.id"
    :photo="photo"
    :index="i"
  />

  <LightboxRoot role="dialog" aria-modal="true" aria-label="Photo viewer">
    <LightboxOverlay />
    <LightboxViewport v-slot="{ photos, viewportRef }">
      <div :ref="viewportRef" class="embla">
        <div class="embla__container">
          <LightboxSlide
            v-for="(photo, i) in photos"
            :key="photo.id"
            :photo="photo"
            :index="i"
          />
        </div>
      </div>
    </LightboxViewport>
    <LightboxControls />
    <LightboxCaption />
    <LightboxGhostImage />
  </LightboxRoot>
</LightboxProvider>
```

Reach for this only when recipe slots and CSS are not enough.

## Picking an entry point

| Need                               | Entry point                          |
| ---------------------------------- | ------------------------------------ |
| A normal gallery or carousel       | Recipes                              |
| One lightbox across several albums | `<PhotoGroup>`                       |
| Custom thumbnail layout            | `<PhotoGroup v-slot>`                |
| Custom lightbox DOM or controls    | Primitives + `useLightboxProvider()` |

Most projects should stay on recipes or grouping.
