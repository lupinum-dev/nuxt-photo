Every built-in thumbnail and lightbox slide resolves through an image adapter. The adapter receives a `PhotoItem` and either the `thumb` or `slide` context, then returns the final image attributes.

::image-pipeline-lab
::

## Choose a provider mode

Configure the app-wide mode under `nuxtPhoto.image`.

| Mode         | Behavior                                                                           |
| ------------ | ---------------------------------------------------------------------------------- |
| `auto`       | Uses Nuxt Image when `@nuxt/image` is registered, otherwise uses native attributes |
| `native`     | Uses `src`, `thumbSrc`, and `srcset` without transforming URLs                     |
| `nuxt-image` | Requires `@nuxt/image` and generates provider-backed URLs and candidates           |
| `false`      | Skips module adapter registration so the application can provide one               |

`auto` is the default and keeps Nuxt Image optional.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxt-photo/nuxt'],
  nuxtPhoto: {
    image: { provider: 'auto' },
  },
})
```

## Native mode preserves supplied sources

For thumbnails, the native adapter uses `thumbSrc` when present and falls back to `src`. For slides, it uses `src` and passes `srcset` through when provided.

```ts [app/data/photos.ts]
export const photos = [
  {
    id: 'coast',
    src: '/photos/coast-2400.jpg',
    thumbSrc: '/photos/coast-480.jpg',
    srcset: '/photos/coast-960.jpg 960w, /photos/coast-1600.jpg 1600w',
    width: 2400,
    height: 1500,
  },
]
```

Choose native mode when the CMS or CDN already returns final URLs and responsive candidates.

## Nuxt Image owns URL generation

Register `@nuxt/image` when thumbnails and slides should use a Nuxt Image provider. Explicit `nuxt-image` mode fails after configured modules finish installing if it is not registered.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxt-photo/nuxt', '@nuxt/image'],
  nuxtPhoto: {
    image: {
      provider: 'nuxt-image',
      thumb: {
        sizes: 'sm:100vw md:50vw lg:400px',
        quality: 80,
      },
      slide: {
        widths: [640, 960, 1240, 1600],
        maxWidth: 1240,
        quality: 85,
      },
    },
  },
})
```

Nuxt Image provider and remote-domain configuration remains in the top-level `image` block. `nuxtPhoto.image` only controls how Nuxt Photo requests thumbnail and slide variants.

## Custom adapters keep the same contract

An `ImageAdapter` returns `src` and optional `srcset`, `sizes`, `width`, and `height`. Pass it to one recipe with `image-adapter`, or provide it for the application after setting `image: false`.

The [custom image service guide]($docs/customization/custom-image-service) shows the provider setup and a typed adapter.

A per-component adapter takes precedence over an injected adapter. Without either, `PhotoImage` falls back to the native adapter.

Custom adapters must be deterministic during SSR. The same photo and context must produce the same attributes on the server and client; generate expiring or signed URLs before render rather than from current time or random state inside the adapter.
