---
title: Server rendering
description: Align server layout assumptions with measured container widths to limit visible movement.
---

The server knows each photo's aspect ratio but cannot measure the browser container. Nuxt Photo combines intrinsic dimensions, an optional initial width, and discrete breakpoints to render useful geometry before hydration.

::ssr-layout-lab
::

## Intrinsic dimensions are the baseline

Every photo requires a positive `width` and `height`. Nuxt Photo validates those values before layout and uses their ratio in the server-rendered markup.

Keep structure CSS enabled. `css: 'structure'` and `css: 'all'` contain the geometry rules used by albums, carousels, and the lightbox. With `css: 'none'`, the application owns all of those rules.

## Rows render without an assumed width

Rows emit a flex-based server layout from photo aspect ratios. When rows use responsive resolver breakpoints, Nuxt Photo can also emit scoped container rules for the discrete layouts.

```vue [app/pages/gallery.vue]
<PhotoAlbum
  :photos="photos"
  :layout="{
    type: 'rows',
    targetRowHeight: responsive({ 0: 160, 640: 220, 1024: 280 }),
  }"
/>
```

This path produces useful server output without guessing a viewport width. The measured client width still becomes authoritative after mount.

## Columns and masonry benefit from an initial width

Columns and masonry need a width to calculate their final groups. Without one, the server renders a simple grid fallback and the client replaces it with the measured layout after mount.

Set `default-container-width` to a realistic content width when that replacement would be visible above the fold.

```vue [app/pages/gallery.vue]
<PhotoAlbum
  :photos="photos"
  :default-container-width="1024"
  :breakpoints="[640, 1024, 1280]"
  :layout="{
    type: 'columns',
    columns: responsive({ 0: 2, 640: 3, 1024: 4 }),
  }"
/>
```

The server calculates this example at 1024px. After mount, the client snaps the measured container down to the largest matching breakpoint. A 1180px container therefore starts at 1024px too.

If the measured width is below the smallest breakpoint, Nuxt Photo keeps the real width. A value of `0` for `default-container-width` has no effect and produces a development warning.

## Use one shared width strategy

Choose `default-container-width` from the same set passed to `breakpoints`. When `responsive()` supplies the breakpoints automatically, ensure the chosen initial width is one of its keys or pass the complete snap set explicitly.

```vue [app/pages/gallery.vue]
<PhotoAlbum
  :photos="photos"
  :default-container-width="1280"
  :breakpoints="[640, 1024, 1280]"
  :spacing="responsive({ 0: 4, 640: 8, 1024: 12 })"
/>
```

An initial width is an application-shell decision, not a device label. Base it on the actual maximum content column and the widths that dominate production traffic.

## Diagnose visible movement

If an album changes shape after hydration, inspect these causes in order:

1. Confirm every photo has its real intrinsic dimensions.
2. Confirm structure CSS is loaded.
3. Compare the initial width with the resolved client breakpoint.
4. For columns or masonry, add a realistic initial width.
5. Test the page at widths immediately below and above each breakpoint.

For carousels, keep `slideAspect` and photo dimensions stable so the media frame retains its height while Embla attaches client-side behavior.
