On a photo page the images cost far more than the script. Get image delivery
right first, then check which components you ship.

## Keep image cost low

- Store the real `width` and `height`, so the browser reserves space before
  each image loads.
- Serve resized files: use Nuxt Image, or `srcset` candidates you prepare.
- Set `sizes` to the width the thumbnail really takes, so the browser does not
  pick a file that is larger than needed.
- Use `thumbSrc` when you have a separate small file for thumbnails.
- Keep images below the first screen lazy (the default).

[Deliver images](/docs/guides/deliver-images) covers each option.

## Bundle size

Production builds, Brotli-compressed. Nuxt rows are the difference from the
same empty Nuxt app. Measured on 1 October 2026 with the 1.0 beta; the
repository's `size` check keeps each value under its limit.

| What the app uses                                | Brotli     |
| ------------------------------------------------ | ---------- |
| Nuxt module enabled, no photo component rendered | `+1.83 kB` |
| Nuxt module with one `PhotoImage`                | `+1.96 kB` |
| Nuxt module with one `PhotoAlbum`                | `+33.5 kB` |
| Vue: `responsive` only                           | `657 B`    |
| Vue: `useLightbox` only                          | `701 B`    |
| Vue: `PhotoImage` only                           | `1022 B`   |
| Vue: the complete package                        | `35.6 kB`  |

`PhotoAlbum` includes the layout, the lightbox, gestures, zoom, and image
handling, so it is the number to compare with other gallery libraries. Nuxt
auto-imports add only the components a page renders.

Measure your own app too. Other modules, route splitting, CSS, and image formats
change what users download.
