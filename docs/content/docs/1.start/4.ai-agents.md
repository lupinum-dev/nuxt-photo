## Agent setup

`@lupinum/nuxt-photo` ships its documentation inside the package, for coding
agents such as Claude Code, Codex and Cursor. The pages match the installed
version, so an agent does not follow the website for a different version.

Give your coding agent this task:

```text
Set up @lupinum/nuxt-photo for coding agents as described under "Agent setup" in its README.
```

In a plain Vue app, name `@lupinum/vue-photo` in the task.

The agent adds one short section to your `AGENTS.md`. The section points at the
pages in `node_modules`; nothing is copied into your project.

### Steps for the agent

1. Find the documentation index of the installed package:

   ```text
   node_modules/@lupinum/nuxt-photo/dist/agent/AGENTS.md
   ```

   Look in the directory of the project that depends on `@lupinum/nuxt-photo` first,
   then in its parent directories up to the repository root. Workspaces can
   hoist packages. Read the file; it lists the documentation pages.

2. Add this section to the project's `AGENTS.md`. Use `CLAUDE.md` if the
   project has only that file. Create `AGENTS.md` if it has neither. If a
   section for `@lupinum/nuxt-photo` already exists, leave it as it is.

   ```md
   ## @lupinum/nuxt-photo

   Before you change code that uses @lupinum/nuxt-photo, read
   `node_modules/@lupinum/nuxt-photo/dist/agent/AGENTS.md` and the pages it
   lists. They document the installed version. Prefer them over what you
   remember about this package and over the website.
   ```

3. Replace the sample path in the section with the path you found:
   - Write it relative to the repository root, through
     `node_modules/@lupinum/nuxt-photo`. In a workspace this can be
     `apps/web/node_modules/@lupinum/nuxt-photo/...`.
   - Never write a resolved path such as `node_modules/.pnpm/...`. It
     contains the version and breaks after an upgrade.

4. Do not copy the documentation into the project and do not install a skill.
   The section points into the installed package, so it stays correct after
   every upgrade or downgrade.

If the file does not exist, the installed version has no packaged
documentation. Read the package README and its TypeScript types instead.

## Read the docs before installing

Every page also has a Markdown version on the site, for an agent that
evaluates Nuxt Photo before it is installed. The complete examples on the
site become code blocks there.

| Source                                                           | Use it for                                  |
| ---------------------------------------------------------------- | ------------------------------------------- |
| [`/llms.txt`](https://nuxt-photo.lupinum.com/llms.txt)           | An index of every page with a description.  |
| `/raw/docs/<page>.md`                                            | One page as Markdown.                       |
| [`/llms-full.txt`](https://nuxt-photo.lupinum.com/llms-full.txt) | All pages in one file, for a large context. |

For example, this page is at
`https://nuxt-photo.lupinum.com/raw/docs/start/ai-agents.md`.

## Connect the MCP server

The docs site runs an MCP server with two read-only tools: `list-pages` and
`get-page`. Add it to an agent that supports remote MCP servers:

```json [.mcp.json]
{
  "mcpServers": {
    "nuxt-photo-docs": {
      "type": "http",
      "url": "https://nuxt-photo.lupinum.com/mcp"
    }
  }
}
```

## Let the types answer first

An agent often reads the installed package before any docs. Every public prop
and `PhotoItem` field has a description in the types, with its default and
whether it can change after mount. Error messages name the fix and link to the
page that explains it. Ask the agent to run your typecheck after a change: most
wrong props and missing fields show up there.
