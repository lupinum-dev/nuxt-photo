---
title: PhotoGroup
description: Give several photo recipes one canonical collection and one shared lightbox.
---

`<PhotoGroup>` separates visual composition from viewer ownership. Its `photos` prop is the only source of identity and next/previous order; descendant `<Photo>` and `<PhotoAlbum>` components contribute trigger elements.

```vue [app/pages/portfolio.vue]
<script setup lang="ts">
const allPhotos = computed(() => [...landscapes.value, ...portraits.value])
</script>

<template>
  <PhotoGroup :photos="allPhotos">
    <section>
      <h2>Landscapes</h2>
      <PhotoAlbum :photos="landscapes" />
    </section>
    <section>
      <h2>Portraits</h2>
      <PhotoAlbum :photos="portraits" />
    </section>
  </PhotoGroup>
</template>
```

## Props

| Prop           | Type                       | Default               | Purpose                                   |
| -------------- | -------------------------- | --------------------- | ----------------------------------------- |
| `photos`       | `readonly PhotoItem[]`     | required              | Canonical identity and navigation order   |
| `imageAdapter` | `ImageAdapter`             | injected, then native | Adapter shared by descendants and slides  |
| `lightbox`     | `boolean \| Component`     | `true`                | Enables, disables, or replaces the viewer |
| `transition`   | `LightboxTransitionOption` | `'auto'`              | Configures shared viewer motion           |

`photos` remains reactive. The provider options are fixed at setup; remount the group to change them.

Every interactive descendant ID must exist in the canonical collection. Missing IDs throw during registration. If a later collection update removes an ID while its thumbnail remains rendered, that thumbnail becomes inert. Duplicate canonical IDs are invalid.

## Slot and template ref

The default slot exposes `{ photos, controller }`. The collection is readonly and follows canonical order. The controller includes the full state and action contract described in the [composables reference]($docs/reference/composables).

The component instance exposes `open`, `openById`, and `close`:

```vue [app/components/FeaturedGallery.vue]
<script setup lang="ts">
const group = useTemplateRef<{
  open(index?: number): Promise<void>
  openById(id: string): Promise<void>
  close(): Promise<void>
}>('group')
</script>

<template>
  <PhotoGroup ref="group" :photos="photos">
    <PhotoAlbum :photos="photos" />
  </PhotoGroup>

  <button type="button" @click="group?.openById('cover')">Open cover photo</button>
</template>
```

Invalid indexes and IDs reject with `RangeError`. A valid open call on a group created with `:lightbox="false"` is a no-op; invalid targets still reject. Programmatic opening can retain a FLIP source when a connected thumbnail for that ID is registered and visible.

`PhotoGroup` is renderless and does not forward `class`, `id`, or other attributes. Put layout and styling attributes on an element inside its slot.

Only one descendant may register a custom slide renderer for a given ID. Registering two renderers for the same photo throws instead of choosing one by mount order.
