---
title: Lightbox primitives
description: Compose custom triggers and viewer markup on the supported lightbox runtime.
---

Use primitives when recipe slots cannot express the required viewer structure. They share state, gesture handling, transitions, focus ownership, and image delivery; the application owns markup and accessibility.

```ts [app/components/CustomGallery.vue]
import {
  LightboxCaption,
  LightboxControls,
  LightboxOverlay,
  LightboxProvider,
  LightboxRoot,
  LightboxSlide,
  LightboxViewport,
  PhotoImage,
  PhotoTrigger,
} from '@nuxt-photo/nuxt/app'
```

## Composition

```vue [app/components/CustomGallery.vue]
<template>
  <LightboxProvider :photos="photos">
    <div class="custom-grid">
      <PhotoTrigger
        v-for="(photo, index) in photos"
        :key="photo.id"
        :photo="photo"
        :index="index"
        v-slot="{ hidden }"
      >
        <PhotoImage :photo="photo" :style="{ opacity: hidden ? 0 : 1 }" />
      </PhotoTrigger>
    </div>

    <LightboxRoot class="np-lightbox" role="dialog" aria-modal="true" aria-label="Photo viewer">
      <LightboxOverlay class="np-lightbox__backdrop" />

      <div class="np-lightbox__ui">
        <LightboxControls
          v-slot="{ activeIndex, count, prev, next, close, controlsDisabled }"
          class="np-lightbox__controls"
        >
          <div class="np-lightbox__topbar">
            <span class="np-lightbox__counter">{{ activeIndex + 1 }} / {{ count }}</span>
            <div class="np-lightbox__actions">
              <button
                type="button"
                class="np-lightbox__btn np-lightbox__btn--prev"
                aria-label="Previous"
                :disabled="controlsDisabled"
                @click="prev"
              >
                &larr;
              </button>
              <button
                type="button"
                class="np-lightbox__btn np-lightbox__btn--next"
                aria-label="Next"
                :disabled="controlsDisabled"
                @click="next"
              >
                &rarr;
              </button>
              <button
                type="button"
                class="np-lightbox__btn np-lightbox__btn--close"
                aria-label="Close"
                @click="close"
              >
                &times;
              </button>
            </div>
          </div>
        </LightboxControls>

        <div class="np-lightbox__stage">
          <LightboxViewport
            v-slot="{ photos, viewportRef, imageLoadFailed }"
            class="np-lightbox__media"
          >
            <div :ref="viewportRef" class="np-lightbox__viewport">
              <div class="np-lightbox__container">
                <LightboxSlide
                  v-for="(photo, index) in photos"
                  :key="photo.id"
                  :photo="photo"
                  :index="index"
                  class="np-lightbox__slide"
                />
              </div>
            </div>
            <p v-if="imageLoadFailed" class="np-lightbox__fallback" role="status">
              Image could not be loaded.
            </p>
          </LightboxViewport>

          <LightboxCaption v-slot="{ photo }" class="np-lightbox__caption">
            <h2 v-if="photo?.caption">{{ photo.caption }}</h2>
            <p v-if="photo?.description">{{ photo.description }}</p>
          </LightboxCaption>
        </div>
      </div>
    </LightboxRoot>
  </LightboxProvider>
</template>
```

Attach `viewportRef` to the viewport element whose direct descendant is the flex slide container. The built-in structure classes preserve the module's structural CSS; custom class names require equivalent rules.

## Primitive contracts

| Primitive          | Props or slot contract                                                                                        |
| ------------------ | ------------------------------------------------------------------------------------------------------------- |
| `LightboxProvider` | Props: `photos`, `transition`, `minZoom`, `imageAdapter`                                                      |
| `LightboxRoot`     | Teleports while open, traps focus, isolates page siblings, renders transition layer                           |
| `LightboxOverlay`  | Closes only when the overlay itself is clicked                                                                |
| `LightboxViewport` | Slot: `{ photos, viewportRef, imageLoadFailed }`                                                              |
| `LightboxSlide`    | Props: `photo`, `index`, `effectClass`, `frameClass`, `zoomClass`, `imgClass`; slot adds `width` and `height` |
| `LightboxControls` | Slot exposes collection state, navigation, close, zoom, and `controlsDisabled`                                |
| `LightboxCaption`  | Slot: `{ photo, activeIndex }`                                                                                |
| `PhotoTrigger`     | Props: `photo`, `index`; slot: `{ photo, index, hidden }`                                                     |
| `PhotoImage`       | Props: `photo`, `context`, `imageAdapter`, `loading`, `sizes`                                                 |

`LightboxRoot` supplies focus behavior but does not add a role, `aria-modal`, or accessible name. Add all three to a custom composition. `LightboxControls` includes an English live region; omit it and build an equivalent localized control region when the application needs different announcements.

Default slide media mounts only for the active and adjacent indexes. A custom slot or registered slide renderer mounts for the active slide. Provider configuration is setup-time, while its photo input may remain reactive.
