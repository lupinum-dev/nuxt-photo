---
title: PhotoAlbum
description: Lay out a validated photo collection in justified rows, balanced columns, or masonry.
---

`<PhotoAlbum>` is the default gallery recipe. It validates the collection, computes layout from intrinsic dimensions, and enables its own lightbox unless a parent group owns one.

```vue [app/pages/gallery.vue]
<script setup lang="ts">
import { responsive, type PhotoItem } from '@nuxt-photo/nuxt/app'

const { data: response } = await useFetch<PhotoItem[]>('/api/photos')
const photos = computed(() => response.value ?? [])
const spacing = responsive({ 0: 4, 640: 8, 1024: 12 })
</script>

<template>
  <PhotoAlbum
    :photos="photos"
    :layout="{ type: 'rows', targetRowHeight: responsive({ 0: 160, 720: 260 }) }"
    :spacing="spacing"
  />
</template>
```

## Props

| Prop                    | Type                                              | Default                | Purpose                                                |
| ----------------------- | ------------------------------------------------- | ---------------------- | ------------------------------------------------------ |
| `photos`                | `readonly PhotoItem[]`                            | required               | Collection to validate and lay out                     |
| `validation`            | `'throw' \| 'drop'`                               | `'throw'`              | Controls invalid-photo handling                        |
| `invalidPhotos` event   | `(event: InvalidPhotosEvent) => void`             | none                   | Reports dropped invalid entries after client rendering |
| `layout`                | `AlbumLayout \| 'rows' \| 'columns' \| 'masonry'` | `'rows'`               | Selects the algorithm and its options                  |
| `spacing`               | `ResponsiveParameter<number>`                     | `8`                    | Gap between items in pixels                            |
| `padding`               | `ResponsiveParameter<number>`                     | `0`                    | Padding around each item in pixels                     |
| `defaultContainerWidth` | `number`                                          | none                   | Seeds deterministic server layout                      |
| `breakpoints`           | `readonly number[]`                               | inferred when possible | Snaps measured client width                            |
| `sizes`                 | rows sizes object                                 | none                   | Computes the image `sizes` attribute for measured rows |
| `imageAdapter`          | `ImageAdapter`                                    | injected, then native  | Overrides image delivery                               |
| `lightbox`              | `boolean \| Component`                            | `true`                 | Enables, disables, or replaces the viewer              |
| `transition`            | `LightboxTransitionOption`                        | `'auto'`               | Configures viewer motion                               |
| `itemClass`             | `string`                                          | none                   | Adds classes to each item wrapper                      |
| `imgClass`              | `string`                                          | none                   | Adds classes to each default image                     |

## Layout values

Rows target `300px` by default. Columns and masonry use `3` columns by default.

```vue [app/components/PhotoLayouts.vue]
<template>
  <PhotoAlbum :photos="photos" :layout="{ type: 'rows', targetRowHeight: 240 }" />
  <PhotoAlbum :photos="photos" :layout="{ type: 'columns', columns: 3 }" />
  <PhotoAlbum :photos="photos" :layout="{ type: 'masonry', columns: 4 }" />
</template>
```

Columns preserve source order within balanced sequential columns. Masonry assigns each next item to the shortest column, so its visual and DOM reading order differs from a simple row sequence.

An explicit non-empty `breakpoints` array replaces inferred `responsive()` breakpoints rather than merging with them. Below the smallest positive breakpoint, the observer keeps the real width.

## Server rendering

Rows render a complete flex fallback without an assumed width. Columns and masonry render a simple grid fallback, then form measured groups after mount. Set a positive `defaultContainerWidth` when server and client should start with the same grouping.

The `sizes` prop is specific to rows. It is computed for measured rows; the container-query branch used without `defaultContainerWidth` does not add a computed `sizes` value.

## Thumbnail slot

`thumbnail` receives `{ photo, index, width, height, hidden }`. It replaces the default `<PhotoImage>`, so render that primitive inside the slot when custom markup should retain the configured adapter.

```vue [app/components/LabeledAlbum.vue]
<template>
  <PhotoAlbum :photos="photos">
    <template #thumbnail="{ photo, hidden }">
      <figure :style="{ opacity: hidden ? 0 : 1 }">
        <PhotoImage :photo="photo" context="thumb" />
        <figcaption>{{ photo.caption }}</figcaption>
      </figure>
    </template>
  </PhotoAlbum>
</template>
```

Inside an enabled `<PhotoGroup>`, the album registers thumbnails with that group and does not create another lightbox. A disabled parent group makes descendant albums inert. Treat `lightbox` and `transition` as setup-time provider choices; photos, layout inputs, `sizes`, and `imageAdapter` remain reactive.
