---
title: Design decisions
description: The constraints Nuxt Photo accepts to make layout, navigation, SSR, and customization predictable.
---

Nuxt Photo is intentionally narrower than a collection of unrelated gallery utilities. The constraints below remove ambiguous state and keep common paths predictable.

## Photos include real dimensions

**Decision:** Every photo provides intrinsic `width` and `height`.

**Why:** Album geometry depends on aspect ratio. Waiting for browser image loads would make layout network-dependent.

**Benefit:** Albums can reserve space during SSR and calculate before images load.

**Cost:** Your CMS, upload pipeline, or asset source must preserve dimensions.

**Result:** The data boundary is stricter; rendering is more stable.

## Collections are explicit

**Decision:** `PhotoGroup.photos` owns identity and navigation order.

**Why:** DOM mount order can change during responsive rendering, keyed moves, and conditional layout.

**Benefit:** Visual composition cannot silently reorder lightbox navigation.

**Cost:** A group receives the full ordered collection as a prop.

**Result:** Every photo collection has one source of truth.

## Responsiveness follows the container

**Decision:** Responsive parameters resolve from gallery width.

**Why:** A gallery can live in a sidebar, split layout, modal, or full-width page at the same viewport size.

**Benefit:** Reusable gallery components respond to the space they actually own.

**Cost:** SSR needs an assumed container width when the final measurement matters above the fold.

**Result:** Components behave correctly wherever they are placed.

## One active modal owner

**Decision:** Only one lightbox owns focus and page isolation at a time.

**Why:** Competing focus traps and inert page state create invalid modal behavior.

**Benefit:** Opening a second lightbox safely hands off modal ownership.

**Cost:** Independent lightboxes do not remain open together.

**Result:** Keyboard and assistive-technology behavior stays defined.

## The public option surface is small

**Decision:** Nuxt Photo exposes library concepts rather than every vendor option.

**Why:** Passing Embla or provider internals through the public API would couple applications to pinned dependencies.

**Benefit:** Vendor upgrades remain contained inside tested adapters.

**Cost:** Uncommon vendor features require a custom composition or another library.

**Result:** The documented API remains the contract.
