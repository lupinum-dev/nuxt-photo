Nuxt Photo gives you four components you can drop into any Nuxt app:

- **`<Photo>`** — a single photo, with an optional solo lightbox.
- **`<PhotoAlbum>`** — a photo grid in rows, columns, or masonry, with a lightbox baked in.
- **`<PhotoGroup>`** — wraps any number of albums so they share a single lightbox.
- **`<PhotoCarousel>`** — an Embla carousel with thumbnails, counter, autoplay, and an optional lightbox overlay.

The lightbox supports pinch-to-zoom, pan, swipe, and FLIP-style transitions. The module auto-registers recipe components, auto-imports helpers by default, detects `@nuxt/image`, and routes thumbnails and slides through the built-in adapter when it is installed.

Nuxt Photo also tracks bundle impact as a consumer would see it. We measure tree-shaking on `@nuxt-photo/core`, focused imports on `@nuxt-photo/vue`, and client-bundle delta for `@nuxt-photo/nuxt` fixture builds in CI.

## Why it exists

Most photo gallery libraries force one trade-off: either the layout is flexible and the lightbox is weak, or the lightbox is rich and the layout is rigid. Nuxt Photo keeps those concerns separate enough that you can start with ready-made components and drop lower only when the default composition is too narrow.

The result is a small set of entry points, not a framework you need to learn from the bottom up.

## Entry points

Start with recipes. Drop lower only when a concrete design needs it.

```text
<Photo>                One photo, optional solo lightbox.
<PhotoAlbum>           Grid layout + lightbox, baked in.
<PhotoGroup>           Share a lightbox across many albums.
<PhotoGroup v-slot>    Your own layout, default lightbox.
<Lightbox> slots       Custom captions, actions, counters, slides.
Primitives + hooks     Custom lightbox structure.
```

## A 10-line gallery

This is the smallest useful thing you can build.

```vue
<script setup lang="ts">
import type { PhotoItem } from '@nuxt-photo/nuxt'

const photos: PhotoItem[] = [
  {
    id: 'landscape',
    src: 'https://picsum.photos/id/1018/1280/800',
    width: 1280,
    height: 800,
    alt: 'Sample landscape photo',
  },
  {
    id: 'portrait',
    src: 'https://picsum.photos/id/1015/960/1200',
    width: 960,
    height: 1200,
    alt: 'Sample vertical photo',
  },
  {
    id: 'wide',
    src: 'https://picsum.photos/id/1020/1200/800',
    width: 1200,
    height: 800,
    alt: 'Sample wide photo',
  },
]
</script>

<template>
  <PhotoAlbum :photos="photos" layout="rows" />
</template>
```

You get a justified-rows layout, a lightbox with gesture support, and server-rendered markup for the default rows path.

## What you get out of the box

- Three layouts: **rows** (justified), **columns**, **masonry**, with responsive breakpoints.
- Touch gestures: pinch-to-zoom, pan, swipe, swipe-to-dismiss.
- FLIP transitions with a `fade` fallback for distant thumbnails.
- A `<PhotoGroup>` that lets several albums share one lightbox and one navigation flow.
- An Embla-powered `<PhotoCarousel>` with thumbnails, counter, arrows, dots, and autoplay.
- Measured client bundle impact, with thresholds checked by `pnpm size`.
- Built-in `@nuxt/image` adapter — auto-detected when the Nuxt Image module is installed.
- Pluggable image adapter for custom CMS or provider pipelines.
- SSR-friendly rows, plus deterministic columns/masonry SSR when dimensions and `defaultContainerWidth` match your layout.
- Importable lightbox primitives (`LightboxRoot`, `LightboxViewport`, `PhotoTrigger`, …) for custom lightbox structure.

## Bundle size and tree-shaking

We document size by import path, not with one “the package is X kB” claim.

- `@nuxt-photo/core` tree-shakes down to small focused imports like `responsive`.
- `@nuxt-photo/vue` has a real spread between focused imports and the full primitive surface.
- `@nuxt-photo/nuxt` is measured as bundle delta, not publish size or raw `dist/` output.
- `<PhotoCarousel>` uses full Embla. We treat it as an intentionally richer feature, not as a tiny primitive.
