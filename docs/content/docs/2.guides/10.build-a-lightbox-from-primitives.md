Build the lightbox from the lower-level components when the built-in structure
cannot match your design. You write the markup and CSS. Nuxt Photo still
handles the photo state, navigation, gestures, zoom, focus, and the opening
animation. You own the final accessibility check.

For a different caption, counter, or buttons,
[the lightbox slots](/docs/guides/customize-the-built-in-lightbox) are enough.

Import the primitives from `@lupinum/nuxt-photo/primitives`, or
`@lupinum/vue-photo/primitives` in plain Vue. This entry is advanced API: it
may change in a minor version, so read the changelog before you update.

## Load the lightbox CSS

`Photo`, `PhotoAlbum`, `PhotoCarousel`, and `PhotoGroup` load the lightbox CSS
together with the viewer, when a visitor first reaches for a photo. A viewer
from primitives does not use that viewer, so load the CSS yourself. Use one of
these:

| Setup                                          | What to do                                                                                                                     |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Nuxt, primitives registered                    | Nothing. With `components: { primitives: true }` the module loads the lightbox CSS on every page, as the `css` option selects. |
| Nuxt, primitives imported from `/primitives`   | Import `@lupinum/nuxt-photo/lightbox.css` in the component, as the example does. It brings the theme too, whatever `css` is.   |
| Plain Vue with `@lupinum/vue-photo/styles.css` | Nothing. `styles.css` contains the lightbox CSS.                                                                               |
| Plain Vue without `styles.css`                 | Import `@lupinum/vue-photo/lightbox.css`.                                                                                      |

`lightbox.css` contains the structure and the theme. Without the structure
CSS, the slides lose their frame area and the backdrop does not cover the page.

`LightboxRoot` renders a native `<dialog>` in `body` and opens it with
`showModal()`. The browser keeps focus inside it and makes the page inert, so
do not add `role="dialog"`, `aria-modal` or a focus trap. Escape runs the
normal close animation. In Safari, Tab reaches buttons only when "Press Tab to
highlight each item" is on; `Option+Tab` always does. The content sits in an
inner `[data-np-lightbox-surface]` element, which is also the fullscreen
target. The structure CSS removes the browser's dialog look: its size limits,
margin, padding, border, background, and `::backdrop`. With `css: 'none'`,
reset these yourself.

Do not pass your own `data-np-motion` or `data-np-slide` attributes to a
primitive. The lightbox sets them and finds the backdrop, viewport, controls,
caption and slides by them.

## Frame the photo and place the caption

The lightbox fits each photo inside a frame area: the full-screen slide minus a
mat on each side. Set the mat with three CSS variables on `LightboxRoot`. The
frame area is measured inside `LightboxViewport`, so give the viewport a
position such as `relative` or `absolute`.

| Variable                  | Default                   | Space it keeps free   |
| ------------------------- | ------------------------- | --------------------- |
| `--np-frame-inset-top`    | `clamp(40px, 7vh, 80px)`  | Above the photo.      |
| `--np-frame-inset-bottom` | `clamp(40px, 7vh, 80px)`  | Below the photo.      |
| `--np-frame-inset-inline` | `clamp(48px, 6vw, 120px)` | Left and right of it. |

Below 700 pixels of screen width the defaults are 24 pixels above and below
and 12 pixels at the sides. The defaults need the structure CSS. Without it,
the photo uses the whole viewport.

The lightbox then sets where the photo is drawn on `LightboxRoot`, in viewport
pixels: `--np-frame-x`, `--np-frame-y`, `--np-frame-width`, and
`--np-frame-height`. The viewer above uses them to put its caption directly
under the photo.

These variables follow the active photo, so a caption placed by them stays put
while a swipe moves the photo. To keep a caption under its own photo during a
swipe, render it in the `#caption` slot of `LightboxSlide` instead:

```vue
<LightboxSlide :photo="photo" :index="i">
  <template #caption="{ photo }">
    <strong v-if="photo.caption">{{ photo.caption }}</strong>
  </template>
</LightboxSlide>
```

The structure CSS places that caption under the frame. The
[primitives reference](/docs/reference/primitives) says when to use which caption primitive.

Keep full-size control layers click-through with `pointer-events: none`, and
turn pointer events back on for the buttons inside. A click that reaches the
viewport beside the photo closes the lightbox.

## Verify the custom structure

Check the behavior that custom markup can affect:

1. Open every thumbnail with click, Enter, and Space.
2. Move through photos with the arrow, Home, and End keys.
3. Close with Escape and confirm focus moves to the thumbnail of the photo you
   were viewing.
4. Confirm the dialog has an accessible name.
5. Test touch swipe, zoom, and reduced motion.
6. Test the layout in left-to-right and right-to-left documents.

Use [the primitives reference](/docs/reference/primitives) for exact props and slot
contracts.
