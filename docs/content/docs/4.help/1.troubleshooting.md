Search this page for the text of your error, or find what you see under
[Symptoms](#symptoms). Nuxt Photo errors start with `[nuxt-photo]` or with the
component name, such as `PhotoAlbum:`.

## Error messages

Each entry quotes the message with example values, such as the photo ID
`canyon`.

### A photo has no `src`

```text
PhotoAlbum: photo "canyon" is missing a non-empty src
```

The photo has no image URL. Check the field you map to `src`.

### `width` or `height` is not a positive number

```text
PhotoAlbum: photo "canyon" has invalid width 0; use the real pixel width of the image file
PhotoAlbum: photo "canyon" has invalid height 0; use the real pixel height of the image file
```

`width` and `height` must be positive numbers: the real pixel size of the image
file. A string such as `"1280"`, `0`, or `NaN` fails. Read the size from
your CMS or at upload; see
[Get the image size at upload](/docs/guides/use-your-photos#get-the-image-size-at-upload).

### `width` or `height` is missing

```text
photo "canyon" has no width; pass width and height, or in Nuxt use localImages / usePhotoFolder for files in public/
```

`width` or `height` is missing or `null`. Pass both. For files in `public/`,
Nuxt can read the sizes for you; see
[Use your own photos](/docs/guides/use-your-photos).

### Two photos share an ID

```text
PhotoAlbum: photos "/photos/canyon.jpg" and "/photos/canyon.jpg" share the id "/photos/canyon.jpg"; give each of them its own `id`
```

Two photos in one collection have the same ID. A photo without `id` uses its
`src`, so the same image twice needs an `id` on each. Use a stable ID from your
data, such as the CMS asset ID, converted to a string. Do not use the array
index: it changes when the order changes.

### An optional field has the wrong type

```text
PhotoAlbum: photo "canyon" field "caption" must be a string
PhotoAlbum: photo "canyon" field "meta" must be an object
```

An optional field has the wrong type, often `null` from an API. Map `null` to
`undefined`: `alt: asset.alt ?? undefined`.

### A photo is missing from its `PhotoGroup`

```text
[nuxt-photo] PhotoGroup descendant photo "canyon" is missing from the canonical photos collection. Add it to the photos of the surrounding <PhotoGroup>, or render it outside the group. See https://nuxt-photo.lupinum.com/docs/reference/photo-group
```

A `Photo` or `PhotoAlbum` inside a `PhotoGroup` shows a photo that is not in the
group's `photos`. Add it to the group's array, which also sets its place in the
lightbox order:

```vue
<PhotoGroup :photos="[...landscapes, ...portraits]">
  <PhotoAlbum :photos="landscapes" />
  <PhotoAlbum :photos="portraits" />
</PhotoGroup>
```

### A lightbox part renders outside a provider

```text
[nuxt-photo] `PhotoTrigger` requires an active lightbox context. Render it inside <LightboxProvider>, or inside a lightbox component passed to a ready-made component. See https://nuxt-photo.lupinum.com/docs/reference/primitives
```

The same error names `LightboxRoot`, `LightboxViewport`, `Lightbox`, or another
lower-level component. It renders outside a provider. Put it inside
`LightboxProvider`, or use it in a lightbox component that you pass to a
ready-made component's `lightbox` prop.

### No photo at this index or ID

```text
[nuxt-photo] No photo found at index 5
[nuxt-photo] No photo found for id "canyon"
```

`open()` or `openById()` got an index or ID that is not in the collection. The
promise rejects with a `RangeError`; catch it when the value comes from a URL
or user input. See [Link to a photo](/docs/guides/control-the-lightbox#link-to-a-photo).

### `lightbox` changed after the component mounted

```text
[nuxt-photo] PhotoAlbum: "lightbox" is a setup-time option; remount the component with a new key to change it
```

This development warning means you changed `lightbox` after the component
mounted. Change the `key` together with it:

```vue
<PhotoAlbum :key="String(showLightbox)" :photos="photos" :lightbox="showLightbox" />
```

### `nuxtPhoto.provider` is set without Nuxt Image

```text
[nuxt-photo] nuxtPhoto.provider requires @nuxt/image; install the module or omit the provider name.
```

Install `@nuxt/image` and add it to `modules`, or remove `nuxtPhoto.provider`.
Without Nuxt Image, every image uses the photo's own `src`, `thumbSrc` and
`srcset`.

### Unknown `nuxtPhoto` option

```text
[nuxt-photo] Unknown `nuxtPhoto.quality` option.
```

`nuxtPhoto` does not know this name, often because of a typo. Compare with
[Configuration and labels](/docs/reference/configuration-and-labels). Image
quality, format and widths belong in your Nuxt Image `image` config; see
[Deliver images](/docs/guides/deliver-images).

### `responsive()` has no breakpoint

```text
[nuxt-photo] responsive() requires at least one breakpoint
```

`responsive({})` has no values. Give at least one width, such as
`responsive({ 0: 2, 768: 3 })`. Keys must be finite numbers of 0 or more.

### The carousel autoplay delay is invalid

```text
[nuxt-photo] PhotoCarousel autoplay.delayMs must be a positive finite number
```

`autoplay.delayMs` is `0`, negative, or not a number. The carousel also rejects
a `loop` or `dragFree` that is not a boolean.

### Hydration mismatch in an album or image

The server and the browser rendered different HTML. Usually an image URL
contains the current time or a random value, or the photo list differs between
server and browser. Create signed URLs before rendering and store them on the
photo, and load the photos with `useFetch` or `useAsyncData`.

## Symptoms

### The album is unstyled or moves while images load

The default `css: 'structure'` places the photos but has no theme. Set
`css: 'all'` for the included look. Keep `'structure'` only when your own CSS
supplies the theme; `'none'` removes the layout CSS too:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@lupinum/nuxt-photo'],
  nuxtPhoto: { css: 'all' },
})
```

Use `css: 'structure'` when your own CSS supplies the visual theme. Every photo
must also have accurate `width` and `height` values. These values let the
browser reserve space before the image loads.

### In plain Vue, `createPhoto` options have no effect in the dev server

The Vite dev server loaded the package twice: once pre-bundled, once as
single-file components. Exclude it from pre-bundling in `vite.config.ts`, as
[Use Nuxt Photo with Vue](/docs/start/plain-vue) shows:
`optimizeDeps: { exclude: ['@lupinum/vue-photo'] }`. Production builds and
Nuxt apps are not affected.

### Selecting a photo does not open a lightbox

`PhotoAlbum` and `PhotoGroup` open a lightbox by default. `Photo` and
`PhotoCarousel` open one only when you set `lightbox`:

```vue
<Photo :photo="cover" lightbox />
<PhotoCarousel :photos="photos" :lightbox="true" />
```

Lower-level components such as `PhotoTrigger` must be inside
`LightboxProvider`.

If `lightbox` was `false` when a ready-made component mounted, changing it to
`true` does not create a provider. Remount the component with a new `:key`, or
mount it only after the option is known. Lightbox capability is a setup-time
option.

### Nuxt Image rejects a remote URL

Add every remote image host to the Nuxt Image `domains` list. Use hostnames,
not complete URLs:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  image: {
    domains: ['images.example.com'],
  },
})
```

On Vercel, images whose width or height is above 8192 px are not optimized.

### A placeholder remains visible

This is expected after the requested image fails. The placeholder stays behind
the broken request instead of leaving an empty frame. It disappears after a
successful load and shows again when the image request changes.

Check the final image URL in the browser network panel. A successful request is
required to remove the placeholder.

### A custom thumbnail ignores image configuration

A raw `<img>` bypasses Nuxt Photo's image provider, `srcset` and placeholder.
Render `PhotoImage` in the slot, and pass it the `sizes` and `priority` that
the `thumbnail` slot gives you. Import it, in Nuxt too:
`import { PhotoImage } from '@lupinum/nuxt-photo/app'`.

### Thumbnails download files that are too large

Open the network panel and compare a thumbnail's file width with its width on
screen times the pixel density:

- On Vercel, the smallest file is the smallest width in `image.screens`. Add
  small screens; see [Deploy on Vercel](/docs/guides/deliver-images#deploy-on-vercel).
- A `sizes` prop on `PhotoAlbum` replaces the layout's own value. Remove it.
- A `<NuxtImg>` in a custom thumbnail slot with `sizes="100vw"` asks for
  screen-wide files. Use `PhotoImage` instead.

### Images appear late while scrolling

The first request for each image width waits until the image service has
transformed it. Check the response headers: on Vercel, `x-vercel-cache: MISS`
means a transform, `HIT` a cached file. Open image-heavy pages once after you
add many images. For remote images on Vercel, raise `minimumCacheTTL`; see
[Deploy on Vercel](/docs/guides/deliver-images#deploy-on-vercel). With IPX on
your own server, keep `format` at `webp`, because AVIF encoding is slow.

### Local images return 404 on Vercel

IPX runs inside a Vercel function, which cannot read `public/`. Use the
`vercel` provider, which Nuxt Image selects by itself on Vercel, or generate a
static site with `nuxt generate`.

### A Nuxt import fails under pnpm

Nuxt applications should import public symbols from
`@lupinum/nuxt-photo/app`, and the lightbox primitives from
`@lupinum/nuxt-photo/primitives`. Importing `@lupinum/vue-photo` directly requires that
package to be installed as a direct dependency.

### RTL changes do not update a carousel

Components read the computed CSS direction of their root. `PhotoCarousel`
reads it at mount. Set `dir` on an ancestor and remount the carousel when the
direction changes:

```vue
<div :dir="localeDirection">
  <PhotoCarousel :key="localeDirection" :photos="photos" />
</div>
```

Lightboxes read the direction again each time they open.

### A click closes the lightbox

A click beside the photo closes the lightbox, and a click on the photo zooms to
its real pixels. In a custom lightbox, a full-screen layer that takes pointer
events catches those clicks first. Give such layers `pointer-events: none` and
turn pointer events back on for the buttons inside them.

### The photos do not fade in a custom lightbox

The fade modes stack the slides with rules from the lightbox structure CSS.
Keep `css: 'structure'` or `css: 'all'`, or stack `[data-np-slide]` elements
yourself. A lightbox built from primitives imported from
`@lupinum/nuxt-photo/primitives` also needs `@lupinum/nuxt-photo/lightbox.css`
once, unless you set `components: { primitives: true }`. That file holds the
lightbox structure and the theme, whatever `nuxtPhoto.css` is. Do not pass your own
`data-np-motion` or `data-np-slide` attributes to a primitive: the lightbox
sets them and finds its parts by them.

### The opening animation jumps

Keep the default `lightbox: { transition: 'auto' }`. It fades when the thumbnail is not visible
enough for a reliable opening animation. Check that thumbnail IDs and dimensions
match the active photo. Programmatic opening without a visible thumbnail also
uses a fade.

### The first open of a photo waits

The lightbox viewer is a separate chunk with its own CSS. It loads when a
pointer, touch or keyboard focus reaches a photo, or when the browser is idle
after a photo became visible. On a slow network, a click that comes before the
chunk has loaded waits for it. With data saving on, the idle load does not
happen. This is expected; [Performance and bundle size](/docs/start/performance-and-bundle-size#what-loads-before-interaction)
explains the timing.

### Tab skips the lightbox buttons in Safari

Safari moves `Tab` only between form fields and links unless "Press Tab to
highlight each item" is on in its settings. `Option+Tab` reaches the lightbox
buttons. Other browsers include them in `Tab`.

After a fix, test selecting a thumbnail, next and previous navigation, Escape,
focus restoration, mobile width, and your application direction.
