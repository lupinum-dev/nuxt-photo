---
title: Upgrade from 0.2 to 1.0
description: Migrate from Nuxt Photo 0.2 to 1.0, or from an earlier 1.0 beta - renamed APIs, root imports, carousel props, strict photos, setup-time lightbox, custom lightbox changes, and a search command to find old code.
---

Nuxt Photo 1.0 removes old APIs instead of keeping two ways to do the same
job, so there are no deprecation aliases. Make these changes when you move from
0.2 to a 1.0 beta or to 1.0. Coming from an earlier 1.0 beta? Start at
[From an earlier 1.0 beta](#from-an-earlier-10-beta).

## Rename provider APIs

Rename the provider composable and shared defaults. There are no deprecated
aliases.

```diff
- import { useLightboxProvider, LightboxDefaultsKey } from '@lupinum/nuxt-photo/app'
+ import { provideLightbox, PhotoDefaultsKey } from '@lupinum/nuxt-photo/app'

- const controller = useLightboxProvider(photos)
+ const controller = provideLightbox(photos)
```

`useLightbox()` remains the consumer composable and `<LightboxProvider>` remains
the template provider.

## Import from the package root

The `@lupinum/vue-photo/composables`, `/provide`, and `/types` subpaths are
removed. Each of them repeated part of the root entry, so import from the root
instead. Nuxt apps keep using `@lupinum/nuxt-photo/app`.

```diff
- import { useLightbox } from '@lupinum/vue-photo/composables'
- import type { LightboxCaptionSlotProps } from '@lupinum/vue-photo/types'
+ import { useLightbox, type LightboxCaptionSlotProps } from '@lupinum/vue-photo'
```

## Use the direct carousel props

Remove the `options` bag and `slidesToScroll`. Nuxt Photo now uses one slide per
snap internally and exposes only the behavior it owns.

```diff
 <PhotoCarousel
   :photos="photos"
-  :options="{ loop: true, dragFree: false, slidesToScroll: 2 }"
+  loop
+  :drag-free="false"
 />
```

Carousel lightboxes are now opt-in. Add `:lightbox="true"` when a carousel
should open the viewer. Use `direction="rtl"` when direction can change at
runtime; otherwise the carousel inherits direction when it mounts.

## Keep strict single photos

`<Photo>` always throws for invalid data. `validation="drop"` remains available
only on collection components (`PhotoAlbum`, `PhotoGroup`, and `PhotoCarousel`),
where the `invalidPhotos` event can make rejected input visible.

Known intrinsic `width` and `height` remain required. Nuxt Photo does not ship a
browser-side dimension measurement helper; resolve dimensions in your CMS,
upload pipeline, or build process.

## Review image and localization behavior

- `PhotoItem.placeholderSrc` adds an optional low-quality preview. The preview
  resets when the resolved source changes and remains visible after load errors.
- `PhotoAlbum.sizes` accepts either a native HTML `sizes` string or the existing
  layout-aware object.
- Localize built-in labels with typed `nuxtPhoto.labels` module options or
  `app.config.ts` values. Indexed templates use `{index}` and slide status also
  uses `{count}`.
- `provider: 'auto'` quietly uses native images when `@nuxt/image` is absent.
  Explicit `nuxt-image` mode still reports a missing module.

## Update programmatic control

Template refs on `PhotoAlbum` and `PhotoGroup` expose one `LightboxHandle`:

```ts
type LightboxHandle = {
  open(index?: number): Promise<void>
  openById(id: string): Promise<void>
  close(): Promise<void>
  readonly isOpen: boolean
}
```

`Photo` and `PhotoCarousel` intentionally do not expose controllers. When an
album belongs to a group, its numeric indexes remain local to that album.

## Treat lightbox capability as setup-time state

The `lightbox` prop decides whether a ready-made component creates a provider when it mounts.
To add, remove, or replace that capability, remount the component with a new Vue
`key`. Photo collections and transition options remain reactive.

## Update advanced custom lightboxes

`LightboxRoot` now owns the transition layer. Remove the old public transition
primitive:

The following before-and-after blocks are migration fragments, not complete
components.

```vue [Migration fragment: before]
<LightboxRoot>
  <LightboxGhostImage class="my-transition-image" />
</LightboxRoot>
```

```vue [Migration fragment: after]
<LightboxRoot>
  <!-- Custom lightbox content -->
</LightboxRoot>
```

The viewport now owns media opacity. Remove the `mediaOpacity` slot binding and
inline style:

```vue [Migration fragment: before]
<LightboxViewport v-slot="{ photos, viewportRef, mediaOpacity }">
  <div :ref="viewportRef" :style="{ opacity: mediaOpacity }">...</div>
</LightboxViewport>
```

```vue [Migration fragment: after]
<LightboxViewport v-slot="{ photos, viewportRef }">
  <div :ref="viewportRef">...</div>
</LightboxViewport>
```

Backdrop blur now accepts a complete CSS filter value:

```css [Migration fragment: app/assets/css/main.css]
.np-lightbox {
  --np-backdrop-filter: blur(16px);
}
```

## Verify the migration

Search for removed names and old carousel configuration:

```bash
rg "useLightboxProvider|LightboxDefaults|slidesToScroll|PhotoCarousel.*options" .
```

Then run `nuxi prepare`, your typecheck, your build, and your browser tests.
Import only from `@lupinum/nuxt-photo`, `@lupinum/nuxt-photo/app`,
`@lupinum/vue-photo`, or `@lupinum/vue-photo/styles.css`. Paths into `dist` or
source folders are not public and can break in any release.

## From an earlier 1.0 beta

The latest betas change these points. Each one matters only if your app uses
the feature.

- **Vue subpaths removed.** Replace imports from `@lupinum/vue-photo/composables`,
  `/provide`, or `/types` with `@lupinum/vue-photo`. Nuxt apps that import from
  `@lupinum/nuxt-photo/app` need no change.
- **Clicks in the lightbox.** A click beside the photo closes the lightbox, and
  a mouse click on the photo zooms. In a lightbox built from primitives, give
  full-screen layers `pointer-events: none` and turn pointer events back on for
  the buttons inside, or those layers catch the clicks.
- **The mat around the photo.** The lightbox now fits each photo inside a mat
  and puts the caption under it. Custom lightboxes can position captions and
  arrows with `--np-frame-x`, `--np-frame-y`, `--np-frame-width`, and
  `--np-frame-height`; see [Build a lightbox from primitives](/docs/guides/build-a-lightbox-from-primitives).
- **New `navigation` option.** `slide` stays the default. The `fade` and
  `crossfade` modes need the structure CSS, or your own rules that stack
  `[data-np-slide]` elements.

The [changelog](https://github.com/lupinum-dev/nuxt-photo/blob/main/packages/vue/CHANGELOG.md)
lists every change per release.
