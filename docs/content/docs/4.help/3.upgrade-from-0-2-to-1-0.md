---
title: Upgrade to 1.0
description: Move from Nuxt Photo 0.2 or an earlier 1.0 beta to 1.0 - one config in nuxt.config, Nuxt Image settings instead of nuxtPhoto.image, provider instead of imageAdapter, priority instead of loading, the lightbox option object, ui classes, carousel controls, history on by default, and a search command that finds old code.
---

Nuxt Photo 1.0 removes old APIs instead of keeping two ways to do the same
job. There are no deprecation aliases: every removed name fails in the type
check or at startup with a message that names the replacement. Start with the
search command, then work through the sections that match what it finds.

## Find old code

```bash [Terminal]
rg "imageAdapter|ImageAdapter|nuxtPhoto\.image|app\.config.*nuxtPhoto|nuxtPhoto:.*image|loading=|imgClass|captionClass|itemClass|slideClass|thumbClass|controlsClass|showArrows|showThumbnails|showCounter|showDots|:direction|LightboxComponentKey|PhotoDefaultsKey|LightboxDefaultsKey|provideLightbox|useLightboxProvider|LightboxHandle|useContainerWidth|resolveResponsiveParameter|slidesToScroll|maxDensity" app
```

After the changes, run `nuxi prepare`, your type check, your build, and your
browser tests.

## Rename props and options

| Before                                                                                     | After                                                                                                                              |
| ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| `:image-adapter="adapter"`                                                                 | `:provider="provider"`, a [`PhotoProvider`](/docs/guides/integrate-a-custom-image-service) or, in Nuxt, a Nuxt Image provider name |
| `loading="eager"`                                                                          | `priority` on `Photo`; `:priority="6"` on `PhotoAlbum` for the first six thumbnails                                                |
| `transition="fade"`, `navigation="crossfade"` on a gallery                                 | `:lightbox="{ transition: 'fade', navigation: 'crossfade' }"`                                                                      |
| `:lightbox="MyLightbox"`                                                                   | `:lightbox="{ component: MyLightbox }"`                                                                                            |
| `img-class`, `caption-class`, `item-class`, `slide-class`, `thumb-class`, `controls-class` | One `ui` object: `:ui="{ img: '…', caption: '…' }"`. Keys per component are in the reference.                                      |
| `:show-arrows`, `:show-thumbnails`, `:show-counter`, `:show-dots` on `PhotoCarousel`       | `:controls="['arrows', 'thumbnails', 'counter']"`, the default. Add `'dots'` or leave items out.                                   |
| `direction="rtl"` on `PhotoCarousel`                                                       | `dir="rtl"` on an ancestor, or CSS `direction`. Every component reads it from the page.                                            |
| `:options="{ loop, dragFree, slidesToScroll }"` on `PhotoCarousel`                         | `loop` and `drag-free` props. Scrolling is one slide per step.                                                                     |
| `LightboxHandle` type                                                                      | `GalleryHandle`. Every component exposes the same handle.                                                                          |

`validation="drop"` now also works on `Photo`: an invalid photo renders
nothing and emits `invalid-photos`.

## Move configuration to nuxt.config

`app.config.ts` no longer configures Nuxt Photo. Move the values to
`nuxtPhoto` in `nuxt.config.ts`:

```diff [nuxt.config.ts]
 export default defineNuxtConfig({
   nuxtPhoto: {
     css: 'all',
-    image: { provider: 'nuxt-image', thumb: { quality: 80 } },
+    labels: 'de',
+    lightbox: { tools: ['download'] },
   },
+  image: { quality: 80 },
 })
```

- **`nuxtPhoto.image` is removed.** Quality, format and widths come from
  your Nuxt Image `image` config; see [Deliver images](/docs/guides/deliver-images).
  `thumb.sizes`, `slide.widths` and `maxDensity` have no replacement: the
  layout writes `sizes`, and the widths come from `image.screens`. On Vercel,
  add the screens from that page.
- **Labels follow the language.** Without `labels`, Nuxt Photo uses the
  active `@nuxtjs/i18n` locale, or English. Nine languages are bundled:
  `en de fr es it nl pt ar he`. `labels: 'de'` picks one; an object overrides
  single labels on top of it.
- **One lightbox component for the app** moves from a plugin with
  `LightboxComponentKey` to `nuxtPhoto.lightbox.component: '~/components/MyLightbox.vue'`.
- **Plain Vue** installs settings with `app.use(createPhoto({ … }))`. The
  injection keys `PhotoDefaultsKey`, `ImageAdapterKey` and
  `LightboxComponentKey` are no longer exported.

An unknown or wrong option now stops `nuxi dev` and `nuxi build` with a
`TypeError` that names it.

## Check changed defaults

- **Back closes the lightbox.** Opening adds a browser history entry. Turn it
  off with `lightbox: { history: false }`; see
  [Control the lightbox](/docs/guides/control-the-lightbox).
- **Images use your Nuxt Image screens.** `srcset` widths now match
  `image.screens` × `densities`, and `sizes` comes from the layout. Expect
  different, usually smaller, image requests.
- **Placeholders appear by themselves** for files in `public/` (with
  `sharp`) and for remote images on IPX. Set `placeholderSrc` to use your
  own.

## Replace removed exports

| Removed                                                | Use instead                                                                      |
| ------------------------------------------------------ | -------------------------------------------------------------------------------- |
| `provideLightbox()`, `useLightboxProvider()`           | `<LightboxProvider :photos="photos">` in the template; `useLightbox()` inside it |
| `ImageAdapter`, `ImageSource`, `ImageContext`          | `PhotoProvider` and `definePhotoProvider({ url })`                               |
| `useContainerWidth`, `resolveResponsiveParameter`      | Nothing: they were internal. Use `responsive()` for responsive layout values.    |
| `@lupinum/vue-photo/composables`, `/provide`, `/types` | `@lupinum/vue-photo`. Nuxt apps import from `@lupinum/nuxt-photo/app`.           |

Import only from `@lupinum/nuxt-photo`, `@lupinum/nuxt-photo/app`,
`@lupinum/vue-photo`, or `@lupinum/vue-photo/styles.css`. Paths into `dist`
or source folders are not public.

## Update a lightbox built from lower-level components

These fragments are not complete components.

`LightboxRoot` owns the opening animation. Remove the old transition
component:

```vue [Migration fragment: before]
<LightboxRoot>
  <LightboxGhostImage class="my-transition-image" />
</LightboxRoot>
```

```vue [Migration fragment: after]
<LightboxRoot>
  <!-- Custom lightbox content -->
</LightboxRoot>
```

The viewport owns image opacity. Remove the `mediaOpacity` binding:

```vue [Migration fragment: before]
<LightboxViewport v-slot="{ photos, viewportRef, mediaOpacity }">
  <div :ref="viewportRef" :style="{ opacity: mediaOpacity }">...</div>
</LightboxViewport>
```

```vue [Migration fragment: after]
<LightboxViewport v-slot="{ photos, viewportRef }">
  <div :ref="viewportRef">...</div>
</LightboxViewport>
```

- A click beside the photo closes the lightbox, and a mouse click on the photo
  zooms. Give full-screen layers `pointer-events: none` and turn pointer
  events back on for the buttons inside, or those layers catch the clicks.
- The photo sits inside a mat with the caption under it. Position captions
  and arrows with `--np-frame-x`, `--np-frame-y`, `--np-frame-width` and
  `--np-frame-height`; see [Build a lightbox from primitives](/docs/guides/build-a-lightbox-from-primitives).
- `--np-backdrop-filter` takes a complete CSS filter, such as `blur(16px)`.
- Only slides next to the open photo are mounted: the open one and one on
  each side. Do not rely on every slide being in the DOM.

lists every change per release.
