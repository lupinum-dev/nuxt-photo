---
title: Upgrade from 1.0.0-beta.8
description: Every breaking change since 1.0.0-beta.8 with before and after code - primitives entry, defaultContainerWidth, optional photo id and duplicate-id, thumbnails by data-np-photo-id, lightbox.css, album and dialog CSS selectors, captions inside their slides, and when lightbox.component mounts.
---

Work through the steps in this order. The first steps break the build, the
middle ones change validation and styling, and the last one changes timing.
An app that uses only `Photo`, `PhotoAlbum`, `PhotoCarousel` and `PhotoGroup`
with the default CSS usually needs step 2 at most.

Coming from 0.2? Read the changelog entries from `1.0.0-beta.1` to
`1.0.0-beta.8` first: they list every breaking change of those releases
([Nuxt package](https://github.com/lupinum-dev/nuxt-photo/blob/main/packages/nuxt/CHANGELOG.md),
[Vue package](https://github.com/lupinum-dev/nuxt-photo/blob/main/packages/vue/CHANGELOG.md)).
Then follow this page.

## 1. Import primitives from their own entry

The lightbox primitives left the root entry. A build that imports them from the
root fails with a missing export.

```ts
// Before
import { LightboxProvider, PhotoTrigger } from '@lupinum/nuxt-photo/app'
// After
import { LightboxProvider, PhotoTrigger } from '@lupinum/nuxt-photo/primitives'
```

In plain Vue, `@lupinum/vue-photo` becomes `@lupinum/vue-photo/primitives`. This
covers `LightboxProvider`, `LightboxRoot`, `LightboxOverlay`, `LightboxAmbient`,
`LightboxViewport`, `LightboxSlide`, `LightboxControls`, `LightboxCaption`,
`PhotoTrigger` and their slot-prop types. `PhotoImage` stays in the root entry.
`components: { primitives: true }` still registers the primitives by name.

## 2. Remove `default-container-width`

`PhotoAlbum` renders `rows`, `columns` and `masonry` from CSS on the server, so
it needs no width guess.

```vue
<!-- Before -->
<PhotoAlbum :photos="photos" layout="rows" :default-container-width="1200" />
<!-- After -->
<PhotoAlbum :photos="photos" layout="rows" />
```

A function value for `spacing`, `padding`, `targetRowHeight` or `columns` is
now called at each planned width, not only at width 0. In `masonry`, keyboard
focus follows `photos` order.

## 3. Check photo IDs

`id` is optional. A photo without `id` uses its `src`, and the `missing-id`
validation code is gone. Two photos with the same resolved ID raise
`duplicate-id`.

```ts
// Before: every photo needed an id
const photos = [{ id: 'canyon', src: '/canyon.jpg', width: 1600, height: 1067 }]
// After: id is optional, but each photo that shares a src needs its own id
const photos = [
  { src: '/lake.jpg', width: 1600, height: 1000 },
  { id: 'canyon', src: '/canyon.jpg', width: 1600, height: 1067 },
  { id: 'canyon-crop', src: '/canyon.jpg', width: 1600, height: 1067 },
]
```

Remove code that checks for the `missing-id` code. Values you read back from
components (slot props, `activePhoto`, `useLightbox().photos`,
`validatePhotos()`) have the type `ResolvedPhotoItem`, with `id: string`.

```ts
// Before
const current = ref<PhotoItem | null>(null)
// After
import type { ResolvedPhotoItem } from '@lupinum/nuxt-photo/app'
const current = ref<ResolvedPhotoItem | null>(null)
```

## 4. Mark custom thumbnails with `data-np-photo-id`

The lightbox finds a thumbnail by its photo ID. This applies only to your own
thumbnail markup in the `PhotoGroup` default slot.

```vue
<!-- Before -->
<PhotoGroup v-slot="{ photos, controller }" :photos="photos">
  <button
    v-for="(photo, index) in photos"
    :key="photo.id"
    :ref="controller.setThumbnailRef(index)"
    :style="{ opacity: controller.hiddenThumbnailIndex.value === index ? 0 : 1 }"
    @click="controller.openById(photo.id)"
  >
    <img :src="photo.src" :alt="photo.alt" />
  </button>
</PhotoGroup>

<!-- After -->
<PhotoGroup v-slot="{ photos, controller }" :photos="photos">
  <button
    v-for="photo in photos"
    :key="photo.id"
    :data-np-photo-id="photo.id"
    :style="{ opacity: controller.hiddenThumbnailId.value === photo.id ? 0 : 1 }"
    @click="controller.openById(photo.id)"
  >
    <img :src="photo.src" :alt="photo.alt" />
  </button>
</PhotoGroup>
```

## 5. Import `lightbox.css` for primitives in Nuxt

The Nuxt module loads the lightbox CSS with the viewer, not on every page. A
lightbox built from primitives imported from `@lupinum/nuxt-photo/primitives`
does not load the viewer, so it needs the CSS once.

```ts
// nuxt.config.ts, after
export default defineNuxtConfig({
  modules: ['@lupinum/nuxt-photo'],
  css: ['@lupinum/nuxt-photo/lightbox.css'],
})
```

`lightbox.css` holds the lightbox structure and the theme, whatever
`nuxtPhoto.css` is. With your own theme, override its variables on
`.np-lightbox`.

Skip this step with `components: { primitives: true }`: then the module still
loads the lightbox CSS on every page. Plain Vue apps that import
`@lupinum/vue-photo/styles.css` need no change.

## 6. Update CSS selectors

The album no longer renders column or skeleton wrappers. The lightbox root is a
native `<dialog>`, and a new `[data-np-lightbox-surface]` element inside it
holds the content.

```css
/* Before */
.np-album__column {
  gap: 8px;
}
.np-album__skeleton {
  background: #eee;
}
[data-np-lightbox-root] > .my-toolbar {
  top: 0;
}

/* After */
.np-album__item {
  border-radius: 4px;
}
/* The skeleton is gone: delete its rules. */
[data-np-lightbox-surface] > .my-toolbar {
  top: 0;
}
```

Move rules for `.np-album__column` to `.np-album__item` or `.np-album__frame`.
Spacing still comes from the `spacing` option.

Remove `role="dialog"` and `aria-modal` from a custom `LightboxRoot`: the
browser makes the page inert and keeps focus in the dialog. The library no
longer sets `inert` or `aria-hidden` on page content either, so remove
selectors and tests that depend on those attributes.

```vue
<!-- Before -->
<LightboxRoot role="dialog" aria-modal="true">…</LightboxRoot>
<!-- After -->
<LightboxRoot>…</LightboxRoot>
```

With `css: 'none'`, reset the browser's dialog styles yourself:

```css
[data-np-lightbox-root] {
  width: auto;
  height: auto;
  max-width: none;
  max-height: none;
  margin: 0;
  padding: 0;
  border: 0;
  overflow: visible;
  color: inherit;
  background: transparent;
}
[data-np-lightbox-root]::backdrop {
  background: transparent;
}
```

## 7. Restyle the caption inside its slide

The built-in lightbox renders each photo's caption inside that photo's slide,
under its frame. The caption moves with its photo during a swipe and has no
transition of its own. Up to three captions exist at once, one per mounted
slide; inactive ones carry `aria-hidden="true"`. `.np-lightbox__caption` and
`.np-lightbox__label` keep their names, and `--np-caption-gap` and
`--np-caption-reserve` keep their meaning.

A rule that placed or animated `.np-lightbox__caption` no longer applies: the
caption is positioned inside the slide frame, not from `--np-frame-*`.

```css
/* Before */
.np-lightbox .np-lightbox__caption {
  top: calc(var(--np-frame-y) + var(--np-frame-height) + 24px);
  transition: top 300ms;
}
.np-lightbox .np-caption-enter-active {
  transition: opacity 400ms;
}

/* After: the gap and the width are the only placement settings */
.np-lightbox {
  --np-caption-gap: 24px;
}
.np-lightbox .np-lightbox__caption {
  --np-caption-width: 100%; /* exactly as wide as the photo */
}
```

Delete rules for `.np-caption-enter-*` and `.np-caption-leave-*`: those classes
are gone. A selector for the one caption, such as
`document.querySelector('.np-lightbox__caption')`, now finds the first mounted
slide's caption; select the active one with
`[data-np-active] .np-lightbox__caption`.

A `#caption` slot on `Lightbox` now renders once for each mounted slide, up to
three times, and its `photo` is never `null`. Remove `null` checks, and keep
ids and side effects out of the slot. Use `LightboxCaption` when you need one
caption for the active photo.

`LightboxAmbient`'s `duration` now applies only when the photo changes without
motion, such as a change from outside. A swipe, a key and the fade modes bring
their own timing.

## 8. Move page-mount code out of `lightbox.component`

The viewer loads when a visitor reaches for a photo. A component you pass as
`lightbox.component` mounts when a photo first opens, not when the page mounts.

Before, `MyLightbox.vue` could start work for the page in its own `onMounted`.
Delete that call from `MyLightbox.vue` and make it in the page:

```vue [app/pages/gallery.vue]
<script setup lang="ts">
import MyLightbox from '~/components/MyLightbox.vue'

const photos = await usePhotoFolder('gallery')

// Runs when the page mounts, as the lightbox component did before.
onMounted(() => startGalleryAnalytics())
</script>

<template>
  <PhotoAlbum :photos="photos" :lightbox="{ component: MyLightbox }" />
</template>
```

## Check

- The build has no missing-export error for `LightboxProvider`, another
  lower-level `Lightbox…` part or `PhotoTrigger`. `Lightbox` itself stays in
  the root entry.
- No `PhotoAlbum` has `default-container-width`.
- Validation reports no `duplicate-id`.
- Opening a photo from your own thumbnails animates from the thumbnail.
- The lightbox looks the same as before, with and without a deep link.
- During a swipe, each caption stays under its own photo.
