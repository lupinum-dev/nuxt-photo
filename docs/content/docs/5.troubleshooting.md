---
title: Troubleshooting
description: Diagnose Nuxt Photo setup, layout, image, and lightbox problems from visible symptoms.
---

Start with the visible symptom, then inspect the data or setting that owns it.

| Symptom                                                    | Likely cause                                                        | Repair                                                                          |
| ---------------------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Rendering throws before the gallery appears                | Missing fields, invalid dimensions, or duplicate IDs                | Normalize the collection against the [photo model]($docs/concepts/photo-model)  |
| The gallery has no usable layout                           | Structure CSS is disabled or replaced incompletely                  | Use `css: 'structure'` or `css: 'all'`                                          |
| Columns or masonry move after hydration                    | The server used the fallback grid                                   | Set a realistic `default-container-width` and matching breakpoints              |
| A grouped descendant throws for an unknown ID              | Its photo is absent from `PhotoGroup.photos`                        | Add the ID to the canonical collection or move the recipe outside the group     |
| A lightbox option changes in state but not on screen       | A setup-time option changed without remounting                      | Change the component `key` with the configuration                               |
| The opening animation starts from the wrong frame          | Photo identity, dimensions, or custom trigger registration is wrong | Keep IDs stable, use real dimensions, and use `PhotoTrigger` for custom layouts |
| Explicit Nuxt Image mode fails during setup                | `@nuxt/image` is not registered                                     | Install and register it, or use `auto` or `native`                              |
| Image configuration works in recipes but not custom markup | The custom slot renders a raw `img`                                 | Render `PhotoImage` or provide the attributes deliberately                      |
| Signed image URLs differ after hydration                   | The adapter reads time or random state during render                | Generate deterministic URLs before rendering                                    |
| A direct Vue import fails under a strict package manager   | The app imports an undeclared package                               | Import from `@nuxt-photo/nuxt/app` or declare `@nuxt-photo/vue` directly        |
| A custom lightbox has duplicate or empty state             | It creates a second provider inside a recipe override               | Consume the provider created by the recipe                                      |
| A carousel does not open a lightbox                        | Carousel lightbox behavior is disabled by default                   | Set `:lightbox="true"`                                                          |

## Fix invalid photo data

Recipe validation checks every consumed field before layout calculation. `PhotoAlbum` and `PhotoCarousel` can use `validation="drop"`, but that mode intentionally removes invalid entries.

Do not use `drop` to hide an unstable API response. Handle `@invalid-photos`, report the issues, and repair the source mapping. This component event is client-only; validate server ingestion at the data boundary. `Photo` and `PhotoGroup` always reject invalid collections.

## Restore structural CSS

The default module setting is `css: 'structure'`. It provides album geometry, carousel layout, lightbox positioning, and transition structure without applying the full visual theme.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxt-photo/nuxt'],
  nuxtPhoto: {
    css: 'structure',
  },
})
```

Choose `css: 'none'` only when the application replaces every structural rule. Utility classes on thumbnails alone are not a complete replacement.

## Align server and client layout widths

For visible movement after hydration, compare the server assumption with the breakpoint selected from the real container. Columns and masonry use a simple server fallback unless `default-container-width` is positive.

The [server rendering concept]($docs/concepts/server-rendering) shows a shared initial-width and breakpoint strategy. Test immediately below and above every breakpoint because that is where a mismatch becomes easiest to see.

## Check provider ownership

Nested recipes should have one provider owner:

- A standalone album owns its viewer.
- Descendants of an enabled `PhotoGroup` delegate to the group.
- A custom recipe lightbox consumes the existing provider.
- A fully custom composition creates one provider around its triggers and primitives.

If two lightboxes are opened independently, Nuxt Photo closes the first before the second takes modal ownership. That handoff is expected and prevents competing focus traps.

## Check setup-time options

Recipe `lightbox`, `transition`, and `imageAdapter` options are captured when the provider is created. Development mode warns when they change without a remount.

```vue [app/components/GallerySettings.vue]
<PhotoAlbum
  :key="`${viewerEnabled}:${transitionMode}`"
  :photos="photos"
  :lightbox="viewerEnabled"
  :transition="transitionMode"
/>
```

Use this pattern for configuration changes, not for ordinary photo updates. Collections remain reactive and preserve the active photo by ID.

## Understand expected fades

`transition="auto"` fades when a thumbnail is too small, mostly outside the viewport, unavailable during close, or no longer mounted. Reduced-motion preference also changes FLIP transitions to a fade.

Force `flip` only when the source thumbnail is consistently available. Use
`fade` when a programmatic action has no registered thumbnail or when the
trigger can move while the viewer is active.

## Run the consumer checks

After changing Nuxt configuration or imports, regenerate the Nuxt types and build the application with the package manager used by the project.

```bash [Terminal]
pnpm exec nuxi prepare
pnpm exec vue-tsc -p .nuxt/tsconfig.app.json --noEmit
pnpm run build
```

Open a thumbnail with pointer and keyboard input, move forward and backward, zoom, close with `Escape`, confirm focus returns to the trigger, and inspect the album at each supported container width.
