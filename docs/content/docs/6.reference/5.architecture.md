This page orients new contributors. It's deliberately short — the code is the
source of truth — but a few things are worth saying once, out loud, that you
can't derive by reading a single file.

## Package shape

Nuxt Photo has two public packages. Nuxt apps install the module package; plain
Vue apps install the Vue package. Internal implementation layers still exist in
source, but they are not separate packages.

```
┌─────────────────────────────────────────────┐
│  @nuxt-photo/nuxt       (auto-imports,      │  module
│                          SSR glue)          │
├─────────────────────────────────────────────┤
│  @nuxt-photo/vue        (components,        │  Vue library
│                          composables,       │
│                          primitives,        │
│                          styles, helpers)   │
└─────────────────────────────────────────────┘
```

- **Vue source** owns components (`PhotoAlbum`, `PhotoCarousel`, `Lightbox`),
  composables (`useLightbox`, `useLightboxProvider`), primitives, styles, and
  framework-free photo helpers.
- **Nuxt source** registers components, auto-imports app-safe helpers from
  `@nuxt-photo/nuxt/app`, wires optional image providers, and handles SSR
  plumbing.

## Lightbox data flow

```
user click on <PhotoTrigger>
      ↓
useLightbox().open(i)
      ↓
carousel.goTo(i)                 ── Embla paging
      ↓
ghost.open(i, callbacks)         ── animation choreography
      │
      ├─► shouldUseFlip          ── chooses FLIP vs FADE for open
      │
      ├─► loadImage              ── decode() → success/failure
      │
      └─► resolves when media visible
      ↓
Vue reactivity re-renders        ── lightbox refs → <Lightbox>
```

The inverse happens on close, via `chooseCloseTransition` (see
[packages/vue/src/core/transition/transitionChoice.ts](https://github.com/lupinum-dev/nuxt-photo/blob/main/packages/vue/src/core/transition/transitionChoice.ts)).

## Design notes

A few decisions that would surprise you reading only one file:

### Why bounded DP for rows layout

Greedy row-packing is fast and often fine, but can trap the final row into
being stubby or unusually tall because earlier rows took too many (or too
few) photos. We use a bounded dynamic-programming search over likely row
breaks, which usually avoids those obvious bad rows without scanning every
possible previous break for large galleries. See
[knuthPlass.ts](https://github.com/lupinum-dev/nuxt-photo/blob/main/packages/vue/src/core/layout/rows/knuthPlass.ts).

### Why row breakpoint CSS exists

The row layout at a given container width is fixed (the divisor in each
item's `width: calc(…)` formula is independent of container width within a
span of breakpoints). We precompute layouts at a set of breakpoints and emit
`@container` rules. Adjacent breakpoints with identical row signatures are
collapsed into a single rule.

Nuxt Photo still measures the album with `ResizeObserver` after mount. The
container-query CSS exists only to make rows render closer to the final layout
before JavaScript has measured the container. See
[containerQueries.ts](https://github.com/lupinum-dev/nuxt-photo/blob/main/packages/vue/src/core/layout/rows/containerQueries.ts).

### Why FLIP with a FADE fallback

FLIP (morphing the thumbnail rect into the viewer rect) gives the strongest
sense of continuity — you're pretty sure the photo you clicked is the one
that grew. It's the default. But FLIP from a thumbnail that's off-screen or
clipped to a few pixels looks like a random zoom from nowhere, so the
transition choice falls back to an overlay FADE when the source rect fails
a visibility check. `prefers-reduced-motion` downgrades to FADE as well. See
[transitionChoice.ts](https://github.com/lupinum-dev/nuxt-photo/blob/main/packages/vue/src/core/transition/transitionChoice.ts).

### Why a dedicated "ghost" element

The FLIP uses a separate absolutely-positioned `<img>` (the ghost) rather
than animating the viewer's own image. Two reasons:

1. The viewer image is only inserted once the full-size source has decoded,
   so it can't carry the transition from the thumbnail.
2. The ghost uses the thumb image adapter source, so the morph starts from the
   same thumbnail URL the page rendered. The slide source decodes in parallel.
   The code only sets `mediaOpacity = 1` after `loadImage()` returns
   `{ ok: true }`; failed loads keep the media layer hidden and render the
   lightbox fallback instead. See
   [openTransition.ts](https://github.com/lupinum-dev/nuxt-photo/blob/main/packages/vue/src/composables/ghost/openTransition.ts).

## Where to look first

| You want to …                    | Start in                                                                                                |
| -------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Understand overall orchestration | `packages/vue/src/composables/useLightboxRuntimeState.ts`                                               |
| Change how rows are packed       | `packages/vue/src/core/layout/rows/knuthPlass.ts`                                                       |
| Tune the open/close animation    | `packages/vue/src/composables/ghost/openTransition.ts` + `closeTransition.ts`                           |
| Change FLIP-vs-FADE rules        | `packages/vue/src/core/transition/transitionChoice.ts`                                                  |
| Add a new image adapter          | `packages/vue/src/core/image/adapter.ts`                                                                |
| Touch input handling             | `packages/vue/src/core/viewer/gestures.ts` + `packages/vue/src/composables/useLightboxInputHandlers.ts` |
| Change spring feel               | `packages/vue/src/composables/usePanzoom.ts`                                                            |
