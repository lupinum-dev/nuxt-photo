Nuxt Photo has one implementation package and one thin Nuxt integration:

```text
@nuxt-photo/nuxt (module registration, SSR integration, app facade)
                         ↓
@nuxt-photo/vue (public components, composables, primitives, and types)
                         ↓
core (framework-light domain logic)
```

`@nuxt-photo/nuxt/app` re-exports the public Vue package. It does not maintain a
second list of app-safe symbols.

## Vue source boundaries

- `components/` contains the four high-level recipes and their local helpers.
- `composables/` contains only public composables.
- `primitives/` contains the headless lightbox building blocks.
- `lightbox/` owns runtime orchestration, transitions, carousel state, pan/zoom,
  and input handling.
- `core/` contains validation, layout, image, geometry, and transition rules that
  do not depend on components.
- `integrations/` contains the narrow vendor boundary.
- `internal/` contains shared Vue implementation details that are not public.

Imports should flow toward the public recipes, never back from core into Vue
components. Nuxt source imports the public Vue package instead of source-tree
internals.

## Lightbox lifecycle

`lightbox/runtime.ts` is the single lifecycle coordinator. Public `open()` and
`close()` calls update the desired intent; one abortable reconciler moves the
runtime through `closed`, `opening`, `open`, and `closing`. `isOpen` is derived
from that status. Starting a conflicting operation aborts the current transition,
so stale image loads and animation continuations cannot publish state later.

```text
controller intent
      ↓
lightbox/runtime.ts ── status + cancellation owner
      ├── carousel.ts
      ├── transitions/**
      ├── panzoom.ts
      └── input/**
```

Transition visual state lives in `lightbox/transitions/state.ts`; it does not own
a second mounted/open flag. Pan/zoom exposes operations to input handling while
keeping raw animation state private. Pointer handling owns one discriminated
gesture session, plus the browser pointer-capture resources it must release.

## Layout design

Rows use a bounded dynamic-programming search so an early greedy choice does not
leave a visibly poor final row. Container-query CSS provides a close SSR-first
layout, then `ResizeObserver` supplies the measured layout after mount. Columns
and masonry use the same `PhotoAlbum.layout` discriminated union, keeping layout
configuration in one place.

## Carousel design

Embla owns motion and drag behavior. Nuxt Photo owns the public option types and
derives dots, counters, thumbnails, and lightbox activation from Embla's actual
geometry-dependent snap registry. The exact-version private read is quarantined
in `integrations/embla/snapModel.ts`; no public declaration mentions Embla. A
vendor upgrade must pass the real-geometry adapter tests before the pin changes.

## Group design

`PhotoGroup.photos` is the only collection and navigation-order source.
Descendants atomically register thumbnail and custom-renderer capability batches
by stable photo ID. Capability registration never constructs or reorders the
photo collection, so Vue mount order and keyed DOM moves cannot change controller
semantics.

## Where to look first

| Change                       | Start in                                                                                     |
| ---------------------------- | -------------------------------------------------------------------------------------------- |
| Photo validation             | `packages/vue/src/core/photo/normalize.ts` and `resolve.ts`                                  |
| Album layout                 | `packages/vue/src/core/layout/**` and `components/photo-album/layoutState.ts`                |
| Recipe behavior              | `packages/vue/src/components/Photo*.vue`                                                     |
| Open/close lifecycle         | `packages/vue/src/lightbox/runtime.ts`                                                       |
| Transition choreography      | `packages/vue/src/lightbox/transitions/**`                                                   |
| Gesture or keyboard behavior | `packages/vue/src/lightbox/input/**`                                                         |
| Pan and zoom                 | `packages/vue/src/lightbox/panzoom.ts`                                                       |
| Carousel mechanics           | `components/photo-carousel/usePhotoCarouselRuntime.ts` and `integrations/embla/snapModel.ts` |
| Nuxt registration            | `packages/nuxt/src/module.ts` and `runtime/**`                                               |

## Change invariants

- A public export change updates exact export tests and this documentation.
- A lifecycle change adds a race or cancellation test in
  `lightboxRuntime.test.ts`.
- A gesture change tests cleanup as well as the happy path.
- A carousel grouping change updates both pure grouping tests and the real Embla
  integration test.
- A package change must pass the packed-consumer release check.
- Setup-time component capabilities remain static; remount with a new `key` to
  change them.
