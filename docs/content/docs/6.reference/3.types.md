Nuxt apps import types from `@nuxt-photo/nuxt/app`. Plain Vue apps import the same types from `@nuxt-photo/vue`.

## `PhotoItem`

```ts [PhotoItem]
interface PhotoItem<TMeta extends object = Readonly<Record<string, unknown>>> {
  readonly id: string
  readonly src: string
  readonly thumbSrc?: string
  readonly width: number
  readonly height: number
  readonly alt?: string
  readonly caption?: string
  readonly description?: string
  readonly srcset?: string
  readonly meta?: Readonly<TMeta>
}
```

`id` and `src` must be non-empty strings. `width` and `height` must be positive, finite intrinsic dimensions. IDs must be unique inside a collection.

Optional text fields must be strings when present. `meta` accepts any non-null object, including a record, array, or class instance. Readonly typing prevents accidental assignment; Nuxt Photo does not freeze or clone application data.

## Validation

Collection recipes accept this policy:

```ts [InvalidPhotoPolicy]
type InvalidPhotoPolicy = 'throw' | 'drop'
```

`'throw'` is the default. `'drop'` removes every invalid item and reports the same issues through the client-side `invalidPhotos` event after rendering.

```ts [InvalidPhotosEvent]
type InvalidPhotosEvent = {
  readonly owner: string
  readonly issues: readonly PhotoValidationIssue[]
  readonly rawPhotos: readonly unknown[]
}
```

Issue codes are `missing-id`, `missing-src`, `invalid-width`, `invalid-height`, `duplicate-id`, `invalid-item`, `invalid-optional-field`, and `invalid-meta`. `PhotoValidationError` is a runtime class with readonly `owner` and `issues` fields.

## Album layouts

```ts [AlbumLayout]
type RowsAlbumLayout = {
  type: 'rows'
  targetRowHeight?: ResponsiveParameter<number>
}

type ColumnsAlbumLayout = {
  type: 'columns'
  columns?: ResponsiveParameter<number>
}

type MasonryAlbumLayout = {
  type: 'masonry'
  columns?: ResponsiveParameter<number>
}

type AlbumLayout = RowsAlbumLayout | ColumnsAlbumLayout | MasonryAlbumLayout
```

The discriminant keeps row height off column layouts and column count off rows. Each numeric value can be static or resolved from the album's container width.

## Carousel options

```ts [PhotoCarouselOptions]
interface PhotoCarouselOptions {
  readonly loop?: boolean
  readonly dragFree?: boolean
  readonly slidesToScroll?: number
}

interface PhotoCarouselAutoplayOptions {
  readonly delayMs?: number
  readonly stopOnInteraction?: boolean
  readonly stopOnMouseEnter?: boolean
}
```

The effective carousel defaults are `loop: false`, `dragFree: false`, and `slidesToScroll: 1`. `slidesToScroll` must be a positive integer. Autoplay delay must be positive and finite; interaction stops autoplay by default, while mouse-enter stopping is opt-in.

## Images

```ts [ImageAdapter]
type ImageContext = 'thumb' | 'slide'

type ImageSource = {
  src: string
  srcset?: string
  sizes?: string
  width?: number
  height?: number
}

type ImageAdapter = (photo: PhotoItem, context: ImageContext) => ImageSource
```

Every adapter must return `src`. Return `width` and `height` when the rendered image should carry intrinsic attributes. The carousel's main frame and the lightbox use the `slide` context; albums, standalone photos, and carousel thumbnails use `thumb`.

## Transitions and responsiveness

```ts [LightboxTransitionOption]
type TransitionMode = 'flip' | 'fade' | 'auto' | 'none'

type LightboxTransitionOption =
  | TransitionMode
  | {
      mode: TransitionMode
      autoThreshold?: number
    }

type ResponsiveParameter<T = number> = T | ((containerWidth: number) => T)
```

`'auto'` is the transition default. It uses FLIP when the source thumbnail has usable geometry, is at least 80 by 80 visible pixels, and meets the default `0.55` visibility threshold; otherwise it fades. Missing geometry can force any animated mode to fall back safely.
