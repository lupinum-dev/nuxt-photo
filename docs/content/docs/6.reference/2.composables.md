Nuxt auto-imports `useLightbox`, `useLightboxProvider`, and `responsive`. Use `@nuxt-photo/nuxt/app` for explicit imports; `useContainerWidth` is explicit-only.

## `useLightbox`

`useLightbox()` reads the nearest provider and returns a readonly controller.

```vue [app/components/GalleryControls.vue]
<script setup lang="ts">
import { useLightbox } from '@nuxt-photo/nuxt/app'

const lightbox = useLightbox()
</script>

<template>
  <button type="button" :disabled="!lightbox.isOpen.value" @click="lightbox.prev()">
    Previous
  </button>
  <span>{{ lightbox.activeIndex.value + 1 }} / {{ lightbox.count.value }}</span>
  <button type="button" :disabled="!lightbox.isOpen.value" @click="lightbox.next()">Next</button>
  <button type="button" @click="lightbox.close()">Close</button>
</template>
```

It must run in a descendant of `<PhotoGroup>`, `<LightboxProvider>`, or a component that called `useLightboxProvider()`. Calling it without a provider throws an actionable error.

```ts [LightboxController]
interface LightboxController {
  readonly photos: ComputedRef<readonly PhotoItem[]>
  readonly count: ComputedRef<number>
  readonly activeIndex: ComputedRef<number>
  readonly activePhoto: ComputedRef<PhotoItem | null>
  readonly isOpen: ComputedRef<boolean>
  open(index?: number): Promise<void>
  openById(id: string): Promise<void>
  close(): Promise<void>
  next(): void
  prev(): void
  toggleZoom(): void
}
```

`open()` defaults to index `0`. Invalid indexes and unknown IDs reject with `RangeError`. `close()` is idempotent; `next()` and `prev()` do nothing while closed or while a transition is active. Viewer navigation loops.

## `useLightboxProvider`

Use `useLightboxProvider()` inside an advanced component that owns the provider and primitive tree.

```ts [app/components/CustomGallery.vue]
const controller = useLightboxProvider(photos, {
  transition: { mode: 'auto', autoThreshold: 0.65 },
  minZoom: 1.5,
  imageAdapter,
  resolveSlide: (photo) => (photo.meta?.kind === 'video' ? renderVideoSlide : null),
})
```

The first argument accepts one photo, a readonly array, or a Vue ref containing
either. Photo changes remain reactive. The options are setup-time
configuration; remount the component to change them.

The return value extends `LightboxController` with:

```ts [LightboxProviderController]
interface LightboxProviderController extends LightboxController {
  readonly hiddenThumbnailIndex: Readonly<Ref<number | null>>
  setThumbnailRef(index: number): (element: Element | ComponentPublicInstance | null) => void
}
```

Do not call this composable inside a component passed to a recipe's `lightbox` prop. The recipe already created the provider that the override consumes.

## `responsive`

`responsive()` turns a minimum-width map into a container-width resolver.

```vue [app/components/PhotoGrid.vue]
<script setup lang="ts">
import { responsive } from '@nuxt-photo/nuxt/app'

const columns = responsive({ 0: 2, 640: 3, 1024: 4 })
</script>

<template>
  <PhotoAlbum :photos="photos" :layout="{ type: 'columns', columns }" />
</template>
```

The largest matching key wins. A width below the smallest key receives that smallest key's value, so include `0` when the map has a base case. Empty maps, negative or non-finite keys, and non-finite container widths throw.

## `resolveResponsiveParameter`

Resolve either a static value or a responsive function with one call:

```ts [app/utils/photo-layout.ts]
const gap = resolveResponsiveParameter(spacing, containerWidth, 8)
```

The fallback is used only when the input value is `undefined`.

## `useContainerWidth`

`useContainerWidth()` measures an element after mount and stays safe during SSR.

```ts [app/composables/useGalleryWidth.ts]
const containerRef = ref<HTMLElement | null>(null)
const { containerWidth } = useContainerWidth(containerRef, {
  defaultContainerWidth: 960,
  breakpoints: [640, 960, 1280],
})
```

The initial value is `defaultContainerWidth` or `0`. With breakpoints, measured
widths snap down to the largest positive breakpoint not greater than the real
width. Widths below the smallest breakpoint remain unsnapped. `breakpoints` may
be a ref when a custom layout changes its snap set at runtime.
