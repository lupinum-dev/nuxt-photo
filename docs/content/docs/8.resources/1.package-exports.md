---
title: Package exports
description: Use the supported Nuxt and Vue entry points without relying on generated deep paths.
---

Nuxt Photo publishes a Nuxt module and a Vue library. Pick one application-facing path and keep imports on its documented surface.

## Nuxt applications

Install `@nuxt-photo/nuxt`, register its module entry, and import runtime values or types from the app facade when auto-imports are not appropriate.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxt-photo/nuxt'],
})
```

```ts [app/components/Gallery.vue]
import { Lightbox, PhotoImage, responsive, type PhotoItem } from '@nuxt-photo/nuxt/app'
```

| Path                   | Contract                                                                   |
| ---------------------- | -------------------------------------------------------------------------- |
| `@nuxt-photo/nuxt`     | Default Nuxt module plus `NuxtPhotoOptions` and `NuxtPhotoAppConfig` types |
| `@nuxt-photo/nuxt/app` | Components, primitives, composables, helpers, keys, and public Vue types   |

The module auto-registers `<Photo>`, `<PhotoAlbum>`, `<PhotoGroup>`, and `<PhotoCarousel>`. It auto-imports `useLightbox`, `useLightboxProvider`, and `responsive`. `<Lightbox>` and `useContainerWidth` remain explicit imports. Primitive registration is opt-in through [module configuration]($docs/reference/configuration).

Nuxt app code does not need a direct `@nuxt-photo/vue` dependency when it imports the same surface from `@nuxt-photo/nuxt/app`.

## Plain Vue applications

Install `@nuxt-photo/vue`, import from its root, and load the complete stylesheet when using rendered components.

```vue [src/App.vue]
<script setup lang="ts">
import { PhotoAlbum, type PhotoItem } from '@nuxt-photo/vue'
import '@nuxt-photo/vue/styles.css'

const photos: PhotoItem[] = [
  {
    id: 'dunes',
    src: '/photos/dunes.jpg',
    width: 1280,
    height: 800,
    alt: 'Dunes at sunset',
  },
  {
    id: 'coast',
    src: '/photos/coast.jpg',
    width: 960,
    height: 1200,
    alt: 'Rocky coast from above',
  },
]
</script>

<template>
  <PhotoAlbum :photos="photos" layout="rows" />
</template>
```

Public Vue paths are:

| Path                          | Contract                                                  |
| ----------------------------- | --------------------------------------------------------- |
| `@nuxt-photo/vue`             | Complete documented runtime and type surface              |
| `@nuxt-photo/vue/composables` | `useLightbox`, `useLightboxProvider`, `useContainerWidth` |
| `@nuxt-photo/vue/provide`     | Documented extension keys and controller types            |
| `@nuxt-photo/vue/types`       | Public lightbox and carousel slot-prop types              |
| `@nuxt-photo/vue/styles.css`  | Structure and bundled theme CSS                           |

## Runtime exports

The Nuxt app facade and Vue root expose the same runtime values:

- Recipes: `Photo`, `PhotoAlbum`, `PhotoGroup`, `PhotoCarousel`, `Lightbox`
- Primitives: `LightboxProvider`, `LightboxRoot`, `LightboxOverlay`, `LightboxViewport`, `LightboxSlide`, `LightboxControls`, `LightboxCaption`, `PhotoTrigger`, `PhotoImage`
- Composables: `useLightbox`, `useLightboxProvider`, `useContainerWidth`
- Responsive helpers: `responsive`, `resolveResponsiveParameter`
- Extension keys: `ImageAdapterKey`, `LightboxComponentKey`, `LightboxDefaultsKey`
- Validation: `PhotoValidationError`

Public types cover photos, layouts, validation, carousel options, image adapters, transitions, responsive values, controllers, and slot props. The [types reference]($docs/reference/types) records the commonly used shapes.

Generated files and undeclared deep paths are not compatibility contracts. Importing a file that happens to exist in the package output can bypass export-map and tree-shaking guarantees even when a local bundler accepts it.
