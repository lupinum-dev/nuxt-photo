---
title: Upgrade to 0.2
description: Move from the 0.1 API to the explicit collections, readonly models, and supported customization surface in 0.2.
---

Use this guide when moving an existing `0.1.x` application to `0.2.0`. Upgrade
the Nuxt and Vue packages as one coordinated set; do not mix APIs or package
versions from the two release lines.

## Runtime requirements

Version 0.2 supports Nuxt `^4.4.8` and Vue `^3.5.0`. Its Node engine is `^22.18.0 || ^24.11.0`. A Nuxt application installs only `@nuxt-photo/nuxt`; that package carries the matching Vue library dependency.

## Normalize photo identity

Every photo now needs a unique, non-empty string ID. Public photo and controller state is readonly.

```ts [app/utils/map-photos.ts]
import type { PhotoItem } from '@nuxt-photo/nuxt/app'

export function mapPhoto(asset: CmsAsset): PhotoItem {
  return {
    id: String(asset.id),
    src: asset.url,
    width: asset.width,
    height: asset.height,
    alt: asset.alt,
  }
}
```

Remove `PhotoMapper`, `itemMapper`, `photoId`, object-identity opening, and `openPhoto`. Map source data at the application boundary, then use `open(index)` or `openById(id)`.

## Give groups one collection

`<PhotoGroup>` no longer discovers a collection from descendants. Pass its complete canonical order explicitly.

```vue [app/pages/gallery.vue]
<template>
  <PhotoGroup :photos="allPhotos">
    <PhotoAlbum :photos="featuredPhotos" />
    <Photo v-for="photo in remainingPhotos" :key="photo.id" :photo="photo" />
  </PhotoGroup>
</template>
```

Every interactive descendant ID must exist in `allPhotos`. Change that array when navigation order changes; visual mount order no longer controls the viewer.

## Move layout options into `layout`

Album-specific values now live in the discriminated layout object.

```vue [app/components/Before.vue]
<template>
  <PhotoAlbum :photos="photos" layout="columns" :columns="3" />
</template>
```

```vue [app/components/After.vue]
<template>
  <PhotoAlbum :photos="photos" :layout="{ type: 'columns', columns: 3 }" />
</template>
```

Use `targetRowHeight` only with `{ type: 'rows' }`, and `columns` only with column or masonry layouts.

## Replace raw carousel options

The carousel accepts library-owned options instead of vendor option or plugin objects.

```vue [app/components/GalleryCarousel.vue]
<template>
  <PhotoCarousel
    :photos="photos"
    :options="{ loop: true, dragFree: false, slidesToScroll: 1 }"
    :autoplay="{ delayMs: 4000, stopOnInteraction: true }"
  />
</template>
```

Remove raw Embla options and `plugins`. The supported option types are listed in the [PhotoCarousel reference]($docs/components/photo-carousel).

## Remount setup-time providers

`lightbox`, `transition`, `imageAdapter`, and provider `minZoom` establish capabilities during setup. Do not expect a prop toggle to create a provider later.

```vue [app/components/SwitchableGallery.vue]
<template>
  <PhotoAlbum
    :key="`${lightboxEnabled}-${transition}`"
    :photos="photos"
    :lightbox="lightboxEnabled"
    :transition="transition"
  />
</template>
```

Photo collections and layout inputs remain reactive.

## Update custom lightboxes

`LightboxRoot` now renders the transition visual itself. Remove `LightboxGhostImage` and the `mediaOpacity` binding from custom primitive compositions.

```vue [app/components/CustomLightbox.vue]
<template>
  <LightboxRoot role="dialog" aria-modal="true" aria-label="Photo viewer">
    <LightboxOverlay />
    <LightboxViewport v-slot="{ photos, viewportRef }">
      <div :ref="viewportRef">
        <div>
          <LightboxSlide
            v-for="(photo, index) in photos"
            :key="photo.id"
            :photo="photo"
            :index="index"
          />
        </div>
      </div>
    </LightboxViewport>
  </LightboxRoot>
</template>
```

Replace the old partial blur variable with a complete filter value:

```css [app/assets/css/main.css]
.np-lightbox {
  --np-backdrop-filter: blur(16px);
}
```

## Update imports

`@nuxt-photo/vue/extend`, the old framework-free engine, and compatibility paths are removed. Nuxt applications use `@nuxt-photo/nuxt/app`; plain Vue applications use the `@nuxt-photo/vue` root or its declared subpaths.

After migration, run the consumer application's normal prepare, type-check, and production build commands. Exercise duplicate-ID validation, grouped navigation order, keyboard opening and closing, reduced-motion transitions, and the real image provider in a browser before deploying the new package set.
