---
title: Build a CMS gallery
description: Normalize external assets once, then render a validated photo collection.
---

Keep CMS fields at the data boundary. The component should receive one valid
`PhotoItem` collection, regardless of which service supplied it.

## Map the response

```vue [app/pages/gallery.vue]
<script setup lang="ts">
import type { PhotoItem } from '@nuxt-photo/nuxt/app'

type Asset = {
  key: string
  url: string
  pixelWidth: number
  pixelHeight: number
  description?: string
}

const { data: assets } = await useFetch<Asset[]>('/api/photos')

const photos = computed<PhotoItem[]>(() =>
  (assets.value ?? []).map((asset) => ({
    id: asset.key,
    src: asset.url,
    width: asset.pixelWidth,
    height: asset.pixelHeight,
    alt: asset.description ?? '',
  })),
)
</script>

<template>
  <PhotoAlbum :photos="photos" layout="rows" />
</template>
```

Use the asset ID rather than its array index. Preserve the original pixel
dimensions, and resolve signed URLs before rendering so the server and client
produce the same `src`.

## Decide how invalid records behave

Albums and carousels throw on invalid photos by default. That is the safest
choice for a CMS contract because the error appears where the bad data enters
the UI.

Use `validation="drop"` only when a partial gallery is better than an error.
Record the event so missing media does not become invisible data loss.

```vue [app/pages/gallery.vue]
<script setup lang="ts">
import type { InvalidPhotosEvent } from '@nuxt-photo/nuxt/app'

function reportInvalidPhotos(event: InvalidPhotosEvent) {
  console.error('CMS returned invalid photos', event.issues)
}
</script>

<template>
  <PhotoAlbum :photos="photos" validation="drop" @invalid-photos="reportInvalidPhotos" />
</template>
```

Before shipping, render the page with JavaScript disabled and confirm that the
server output reserves the correct space. Then open the final photo and verify
that lightbox navigation follows the CMS collection order. The [photo model]($docs/concepts/photo-model)
lists every validation rule.
