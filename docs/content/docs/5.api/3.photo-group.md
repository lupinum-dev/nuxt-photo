---
title: PhotoGroup API
description: Give several photo recipes one explicit collection and shared lightbox.
---

`<PhotoGroup>` lets descendant `<Photo>` and `<PhotoAlbum>` recipes share one
lightbox. Its required `photos` prop is the sole source of identity and
navigation order. Descendants contribute only their thumbnail elements and
optional custom slide renderers.

::collection-ownership-lab
::

Changing visual descendant order never changes controller order accidentally.
To change navigation order, change the canonical `photos` collection.
Every interactive descendant ID must exist in that collection; a mismatch
throws during capability registration instead of failing on a later click.
If a reactive collection later removes an ID while its descendant remains
rendered, that descendant becomes inert immediately.

## Props

| Prop           | Type                       | Default                 | Description                                      |
| -------------- | -------------------------- | ----------------------- | ------------------------------------------------ |
| `photos`       | `readonly PhotoItem[]`     | -                       | **Required.** Canonical collection and order.    |
| `imageAdapter` | `ImageAdapter`             | provided/module default | Per-group image adapter override.                |
| `lightbox`     | `boolean \| Component`     | `true`                  | Enable, disable, or replace the lightbox recipe. |
| `transition`   | `LightboxTransitionOption` | `'auto'`                | Reactive FLIP/fade configuration.                |

The photo collection, lightbox override, and transition configuration are
reactive. Removing an override restores the library default.

## Default slot

The default slot exposes `{ photos, controller }`. `photos` is readonly and
matches the canonical prop order. Use the controller when a toolbar inside the
group needs the complete lightbox API.

## Programmatic control

```vue
<script setup lang="ts">
const groupRef = ref<{
  open(index?: number): Promise<void>
  openById(id: string): Promise<void>
  close(): Promise<void>
}>()
</script>

<template>
  <PhotoGroup ref="groupRef" :photos="photos">
    <PhotoAlbum :photos="photos" />
  </PhotoGroup>

  <button @click="groupRef?.open(3)">Open fourth photo</button>
  <button @click="groupRef?.openById('desert-01')">Open desert</button>
</template>
```

Invalid indexes and IDs reject with a namespaced `RangeError`. `close()` is
idempotent. A group mounted with `:lightbox="false"` stays inert; remount it to
enable a provider.

## Opting out one thumbnail

The canonical collection can contain a photo whose visual `<Photo>` trigger is
inert:

```vue
<PhotoGroup :photos="photos">
  <Photo :photo="photos[0]" />
  <Photo :photo="photos[1]" lightbox-ignore />
</PhotoGroup>
```

The ignored photo remains available through programmatic navigation because
`photos` owns the collection. Only that particular thumbnail is inert.

## Custom layouts

For a bespoke layout without recipe components, compose the explicit primitives:

```vue
<script setup lang="ts">
import { Lightbox, LightboxProvider, PhotoTrigger } from '@lupinum/nuxt-photo/app'
</script>

<template>
  <LightboxProvider :photos="photos">
    <div class="hex-grid">
      <PhotoTrigger
        v-for="(photo, index) in photos"
        :key="photo.id"
        :photo="photo"
        :index="index"
        v-slot="{ hidden }"
      >
        <img
          :src="photo.thumbSrc ?? photo.src"
          :alt="photo.alt"
          :style="{ opacity: hidden ? 0 : 1 }"
        />
      </PhotoTrigger>
    </div>
    <Lightbox />
  </LightboxProvider>
</template>
```
