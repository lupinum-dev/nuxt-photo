---
title: PhotoGroup
description: Collect descendant photos into one shared lightbox.
---

`<PhotoGroup>` has one job: descendant `<Photo>` and `<PhotoAlbum>` components
register into one shared lightbox, in render order.

::demo-code-pair
::demo-group
::

```vue [code]
<template>
  <PhotoGroup>
    <h2>Landscapes</h2>
    <PhotoAlbum :photos="landscapes" layout="rows" />

    <h2>Studies</h2>
    <PhotoAlbum :photos="studies" layout="columns" />
  </PhotoGroup>
</template>
```

::

Clicking a photo in either album opens the same lightbox. Inserts, removals,
and reorders stay synchronized. Duplicate IDs across different children throw
a `PhotoValidationError` instead of creating ambiguous navigation.

## Props

| Prop           | Type                       | Default                 | Description                                      |
| -------------- | -------------------------- | ----------------------- | ------------------------------------------------ |
| `imageAdapter` | `ImageAdapter`             | provided/module default | Per-group image adapter override.                |
| `lightbox`     | `boolean \| Component`     | `true`                  | Enable, disable, or replace the lightbox recipe. |
| `transition`   | `LightboxTransitionOption` | `'auto'`                | Setup-time FLIP/fade configuration.              |

Provider-level props are setup-time options. Remount the group with a new
`key` to change them. Photos remain reactive.

## Programmatic control

```vue
<script setup lang="ts">
const groupRef = ref<{
  open(index?: number): Promise<void>
  openById(id: string): Promise<void>
  close(): Promise<void>
}>()
</script>

<template>
  <PhotoGroup ref="groupRef">
    <PhotoAlbum :photos="photos" />
  </PhotoGroup>

  <button @click="groupRef?.open(3)">Open fourth photo</button>
  <button @click="groupRef?.openById('desert-01')">Open desert</button>
</template>
```

Invalid indexes and IDs reject with a namespaced `RangeError`. `close()` is
idempotent. A group mounted with `:lightbox="false"` stays inert; remount it to
enable a provider.

## Opting out one photo

```vue
<PhotoGroup>
  <Photo :photo="featured" />
  <Photo :photo="decorative" lightbox-ignore />
  <PhotoAlbum :photos="archive" />
</PhotoGroup>
```

`lightbox-ignore` applies to `<Photo>` registration only.

## Custom layouts use primitives

PhotoGroup does not accept a `photos` prop or manufacture trigger attribute
bags. For a bespoke layout, compose the explicit primitives:

```vue
<script setup lang="ts">
import { Lightbox, LightboxProvider, PhotoTrigger } from '@nuxt-photo/nuxt/app'
</script>

<template>
  <LightboxProvider :photos="photos">
    <div class="hex-grid">
      <PhotoTrigger
        v-for="(photo, index) in photos"
        :key="photo.id"
        :photo="photo"
        :index="index"
        v-slot="{ hidden }"
      >
        <img
          :src="photo.thumbSrc ?? photo.src"
          :alt="photo.alt"
          :style="{ opacity: hidden ? 0 : 1 }"
        />
      </PhotoTrigger>
    </div>
    <Lightbox />
  </LightboxProvider>
</template>
```
