---
title: Create a custom thumbnail layout
description: Keep Nuxt Photo lightbox behavior while owning every thumbnail position.
---

Use `LightboxProvider`, `PhotoTrigger`, and `PhotoImage` when rows, columns, and
masonry do not fit the design. The provider owns the collection; your template
owns the layout.

```vue [app/components/ContactSheet.vue]
<script setup lang="ts">
import { Lightbox, LightboxProvider, PhotoImage, PhotoTrigger } from '@nuxt-photo/nuxt/app'
import type { PhotoItem } from '@nuxt-photo/nuxt/app'

defineProps<{ photos: readonly PhotoItem[] }>()
</script>

<template>
  <LightboxProvider :photos="photos">
    <div class="contact-sheet">
      <PhotoTrigger
        v-for="(photo, index) in photos"
        :key="photo.id"
        v-slot="{ hidden }"
        :photo="photo"
        :index="index"
      >
        <PhotoImage :photo="photo" context="thumb" :style="{ opacity: hidden ? 0 : 1 }" />
      </PhotoTrigger>
    </div>

    <Lightbox />
  </LightboxProvider>
</template>
```

`PhotoTrigger` supplies click, Enter, and Space activation plus the thumbnail
ref used by FLIP transitions. Respect its `hidden` slot prop so the thumbnail
does not remain visible beneath the transition image. `PhotoImage` preserves
the active image adapter for the custom layout.

Use `PhotoGroup` instead when the custom layout is built from descendant
`Photo` or `PhotoAlbum` recipes. Use a provider when you need direct primitive
control over each trigger.
