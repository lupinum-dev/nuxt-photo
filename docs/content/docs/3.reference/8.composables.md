description: Public helpers for lightbox state, reactive labels, async local folders, photo validation, providers, and responsive values.

Nuxt auto-imports `useLightbox`, `usePhotoLabels`, `usePhotoFolder`, and
`responsive` unless `autoImports` is disabled. All APIs below can be imported
from `@lupinum/nuxt-photo/app`. `usePhotoFolder` is Nuxt-only.

## `useLightbox()`

```ts [useLightbox]
function useLightbox<
  TMeta extends object = Readonly<Record<string, unknown>>,
>(): LightboxController<TMeta>
```

Call during setup in a descendant of `LightboxProvider`, `PhotoGroup`, or a
ready-made component's custom viewer. It throws without an active context.
It returns readonly computed refs: `photos`, `count`, `activeId`,
`activeIndex`, `activePhoto`, and `isOpen`. Its actions are
`open(index?: number): Promise<void>`, `openById(id: string): Promise<void>`,
`close(): Promise<void>`, `next(): void`, `prev(): void`, and
`toggleZoom(): void`. `open()` defaults to index `0`. Invalid indexes or IDs
reject with `RangeError`. Use `LightboxProvider` to create a custom collection.

## `usePhotoLabels()`

```ts [usePhotoLabels]
function usePhotoLabels(): PhotoLabels
```

Returns the complete labels as properties, rather than refs. Property reads
follow the current locale and per-key overrides. Read them in templates or
computed values to retain reactivity; copying a string stores its current
value. See [configuration and labels](/docs/reference/configuration-and-labels).

## `usePhotoFolder()`

```ts [usePhotoFolder]
function usePhotoFolder(
  folder: string,
  options?: {
    alt?: Record<string, string>
    caption?: Record<string, string>
    sort?: 'name' | 'name-desc'
  },
): Promise<Ref<PhotoItem[]>>
```

Await it during Nuxt setup. It returns a mutable, deeply reactive ref.
`folder` is relative to `public/`; surrounding slashes are removed. Only files
in that folder are included, without nested folders. IDs are paths relative
to `public/`, without the extension. `alt` and `caption` maps use the filename
without its extension, not the full path. Default sort is `name`, ordered by
ID with a locale-independent string comparison; `name-desc` reverses it.

```vue [app/pages/gallery.vue]
<script setup lang="ts">
import { PhotoAlbum, usePhotoFolder } from '@lupinum/nuxt-photo/app'
const photos = await usePhotoFolder('photos', {
  alt: { coast: 'Rocky coastline' },
})
</script>

<template>
  <PhotoAlbum :photos="photos" />
</template>
```

The server uses the build-time public image manifest. Only the requested
folder's records, including dimensions and available placeholders, transfer
through the Nuxt payload; hydration reuses that payload. The payload key
includes the normalized folder, sort, and sorted label map entries. This works
with `localImages: false` and does not send the whole manifest to the client.
A client request without cached payload fetches that folder from the server.
An empty or unknown folder returns an empty array. Development warns once per
folder when it is empty or contains photos without alt text.

## `validatePhotos()`

```ts [validatePhotos]
function validatePhotos(
  input: unknown[],
  options?: { owner?: string },
): { photos: PhotoItem[]; issues: PhotoValidationIssue[] }
```

Returns valid photos and issues without throwing or modifying the input.
The default owner is `validatePhotos`. Invalid photos and all occurrences of
a duplicate ID are dropped. It does not resolve missing dimensions from app
configuration; supply dimensions before calling it.

## `definePhotoProvider()`

```ts [definePhotoProvider]
function definePhotoProvider<T extends PhotoProvider>(provider: T): T
```

Returns the same object and preserves its inferred type. This helper does not
validate at runtime. `url(src, { width, quality?, format? })` is required;
`placeholder(src)` and `srcset(photo, context)` are optional. The provider
owns URLs, not image `sizes`. See [PhotoProvider](/docs/reference/types#photoprovider).

## `responsive()`

```ts [responsive]
function responsive<T>(breakpoints: Record<number, T>): (containerWidth: number) => T
```

Keys are minimum container widths in pixels. The greatest matching key wins;
below every key, the smallest key's value wins. The returned function carries
breakpoint metadata used by `PhotoAlbum` for measurement snapping.

```ts [app/utils/gallery.ts]
import { responsive } from '@lupinum/nuxt-photo/app'
export const columns = responsive({ 0: 2, 640: 3, 1024: 4 })
```

An empty map throws. Keys must be finite and non-negative; the input width
must be finite. `PhotoAlbum` already measures its container.
