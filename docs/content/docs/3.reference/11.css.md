Nuxt Photo ships three CSS strategies, controlled by the `css` module option:

```ts [nuxt.config.ts]
nuxtPhoto: {
  css: 'structure' // 'none' | 'structure' | 'all'
}
```

| Value         | Loaded content                                 |
| ------------- | ---------------------------------------------- |
| `'none'`      | No stylesheets. You write every rule yourself. |
| `'structure'` | Layout + geometry only. **Default.**           |
| `'all'`       | Structure + the default theme.                 |

## Class naming

Ready-made components use `np-` classes with double-underscore and double-dash notation.
PhotoGroup has a `display: contents` wrapper without a built-in class.
Primitives also expose the data attributes listed below:

You do not need to override these rules directly. Use CSS variables and the component `ui` object for class targets.

## CSS variables

The theme CSS uses variables scoped to the relevant root. Override them globally in your app CSS or per-component.

### Lightbox

The lightbox hangs each photo in a mat, like a framed print, with its caption
underneath. The structure CSS sets the mat; the theme CSS sets the look.

```css
.np-lightbox {
  /* Mat and caption room (structure CSS) */
  --np-frame-inset-top: 72px;
  --np-frame-inset-bottom: calc(var(--np-caption-reserve) + 16px);
  --np-frame-inset-inline: clamp(80px, 7vw, 120px);
  --np-caption-reserve: 104px; /* height kept free for the caption */
  --np-caption-gap: 14px; /* space between photo and caption */

  /* Room (theme CSS) */
  --np-backdrop-bg: #0c0c0e;
  --np-backdrop-filter: none;
  --np-ambient-opacity: 0.45; /* 0 turns the glow off */

  /* Controls */
  --np-btn-radius: 999px;
  --np-btn-bg: rgba(22, 22, 25, 0.62);
  --np-btn-hover-bg: rgba(48, 48, 54, 0.78);
  --np-btn-color: #f4f3f0;
  --np-btn-border: rgba(255, 255, 255, 0.12);
  --np-btn-shadow: 0 8px 24px rgba(0, 0, 0, 0.24);
  --np-btn-blur: 10px;
  --np-btn-disabled-opacity: 0.35;
  --np-focus-ring: #f4f3f0;
  --np-counter-color: rgba(244, 243, 240, 0.82);

  /* Photo */
  --np-img-radius: 6px;
  --np-img-shadow: 0 30px 80px rgba(0, 0, 0, 0.45), 0 2px 10px rgba(0, 0, 0, 0.35);

  /* Caption */
  --np-caption-color: #f4f3f0;
  --np-caption-heading-size: 17px;
  --np-caption-secondary: rgba(244, 243, 240, 0.66);
}
```

Override any of them in your global CSS:

```css
/* A tighter mat, a plain room, and square corners */
.np-lightbox {
  --np-frame-inset-inline: 72px;
  --np-ambient-opacity: 0;
  --np-img-radius: 0;
}
```

Below 700 pixels of screen width the ready-made lightbox uses a smaller mat:
`--np-frame-inset-top: 64px`, `--np-frame-inset-inline: 12px`, and
`--np-caption-reserve: 96px`, with the bottom inset 12 pixels above the
caption. The previous and next arrows are hidden there until they receive
keyboard focus, because swiping changes the photo.

While the lightbox is open, it also sets where the photo is drawn on its root, in
viewport pixels: `--np-frame-x`, `--np-frame-y`, `--np-frame-width`, and
`--np-frame-height`. The caption and arrows use them to stay next to the photo.

`--np-caption-width` defaults to
`min(max(var(--np-frame-width, 100vw), 320px), calc(100vw - 24px))`. It sets
the caption width and keeps its inline position inside the viewport.

### Carousel

```css
.np-carousel {
  --np-carousel-gap: 0.75rem;
  --np-carousel-slide-size: 100%;
  --np-carousel-slide-aspect: 16 / 10;
  --np-carousel-thumb-size: 5.5rem;
  --np-carousel-thumb-gap: 0.5rem;
  --np-carousel-radius: 0.5rem;
  --np-carousel-surface: rgba(0, 0, 0, 0.55);
  --np-carousel-surface-fg: #fff;
  --np-carousel-thumb-border: rgba(0, 0, 0, 0.1);
}
```

Slide size, aspect, and thumb size can also be set via props (`slideSize`, `slideAspect`, `thumbSize`). The prop wins over the variable.

### Album

Albums are mostly structural: spacing and padding come from props. For ready-made components, structure CSS is part of the layout contract, not decorative theme CSS.

## Why the structure CSS is required

The structure CSS contains layout rules that are difficult to reproduce with Tailwind or other utility CSS:

- Rows layout uses a trailing `<span style="flex-grow:9999">` ghost to absorb remaining space.
- Columns and masonry use nested `.np-album__column` children with explicit gap math.
- The lightbox viewport coordinates CSS custom properties set by JavaScript (zoom state, pan offsets, gesture translate).

The `css: 'none'` setting requires a complete replacement for these rules. Use it only with a custom gallery CSS system.

## Add classes with ui

Ready-made components accept a `ui` object. Its classes merge with the built-in classes:

```vue
<PhotoAlbum
  :photos="photos"
  :ui="{
    item: 'rounded-lg overflow-hidden shadow-lg',
    img: 'transition-transform hover:scale-105',
  }"
/>
```

Use this option for hover states, border treatments, and shadow effects that do not need custom layout calculations.

## Style from scoped CSS

Vue scoped styles rewrite class selectors. Therefore, a `<style scoped>` block cannot target `.np-album__item` directly. Use `:deep()`:

```vue
<style scoped>
.my-album :deep(.np-album__item) {
  border: 2px solid var(--accent);
}
</style>
```

## Turn off all CSS

```ts [nuxt.config.ts]
nuxtPhoto: {
  css: 'none'
}
```

::warning
Without the structure CSS, the grid calculations fail and photos collapse to zero-size boxes. Select `'none'` only when you provide a complete replacement.
::

`ui` keys are `root`, `img`, and `caption` for Photo; `root`, `item`, and `img`
for PhotoAlbum; `root` for PhotoGroup; and `root`, `slide`, `img`, `thumb`,
`caption`, and `controls` for PhotoCarousel. The object adds classes; it does
not replace built-in geometry. Primitives use normal classes and slots;
LightboxSlide also has effect, frame, and zoom wrapper class props.

PhotoImage renders an available preview as an inline background image. The
preview stays after a failed image request. Its background size is `cover`,
with centered positioning and no repeat.
