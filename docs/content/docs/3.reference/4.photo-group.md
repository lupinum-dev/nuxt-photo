title: PhotoGroup
description: The PhotoGroup component - props, events, slot, and template ref for one lightbox and navigation order across several albums and photos.
---

`PhotoGroup` owns one ordered collection and lightbox. Descendant `Photo` and
`PhotoAlbum` components register triggers by stable photo ID.

## Minimal usage

```vue [app/pages/portfolio.vue]
<script setup lang="ts">
import type { PhotoItem } from '@lupinum/nuxt-photo/app'

const photos: PhotoItem[] = [
  { id: 'one', src: '/photos/one.jpg', width: 1200, height: 800, alt: 'Coastline' },
  { id: 'two', src: '/photos/two.jpg', width: 800, height: 1200, alt: 'Pine tree' },
]
</script>

<template>
  <PhotoGroup :photos="photos">
    <PhotoAlbum :photos="photos" />
  </PhotoGroup>
</template>
```

## Props

`active` is optional (`string | null`, default `undefined`) and reactive.
`v-model:active` sets the lightbox photo ID; `null` closes it. User navigation
emits `update:active`. An unknown ID is ignored with a development warning.

`lightbox` accepts `boolean | LightboxOptions`. Its enabled state and
`component` are setup-time: remount with a new `key` to change them.
The options inherit [configuration defaults](/docs/reference/configuration-and-labels).
`minZoom` is setup-time. Other lightbox options are read reactively; changing
`deepLink` does not repeat the initial URL lookup.

| Prop           | Type                       | Default                 | Description                                                       |
| -------------- | -------------------------- | ----------------------- | ----------------------------------------------------------------- |
| `photos`       | `readonly PhotoItem[]`     | -                       | **Required.** Canonical collection and order.                     |
| `validation`   | `'throw' \| 'drop'`        | inherited (`'throw'`) | Invalid collection policy.                                        |
| `lightbox`     | `boolean \| LightboxOptions`     | `true`                  | Enable, disable, or replace the lightbox.                         |
| `active` | `string \| null` | `undefined` | Lightbox photo ID; reactive. |
| `provider` | `PhotoProvider \| string` | inherited | Image delivery; reactive. A name requires Nuxt Image. |
| `ui` | `PhotoUi<'PhotoGroup'>` | `undefined` | Classes merged onto built-in classes; reactive. |

## Events

| Event           | Payload              | When it fires                                               |
| --------------- | -------------------- | ----------------------------------------------------------- |
| `invalidPhotos` | `InvalidPhotosEvent` | Invalid entries are found while `validation="drop"` is set. |
| `update:active` | `string \| null` | Lightbox opens, navigates, or closes. |

```vue
<PhotoGroup :photos="photos" validation="drop" @invalid-photos="reportInvalidPhotos">
  <PhotoAlbum :photos="photos" />
</PhotoGroup>
```

## Slots

| Slot      | Props                    | Purpose                                              |
| --------- | ------------------------ | ---------------------------------------------------- |
| `default` | `{ photos, controller }` | Render group content and access the full controller. |

The slot `photos` value is readonly and keeps the canonical prop order.
`controller` includes the `LightboxController` fields, plus
`hiddenThumbnailIndex: Readonly<Ref<number | null>>` and
`setThumbnailRef(index: number)`, a callback that registers a thumbnail element.
Child lightbox options are ignored with one development warning; the group
owns the viewer.

## Exposed template-ref API

The exposed `GalleryHandle` has `open(index?: number): Promise<void>`,
`openById(id: string): Promise<void>`, and `close(): Promise<void>`.
`open()` defaults to index `0`. Its readonly state is `isOpen: boolean`,
`activeId: string | null`, and `activePhoto: PhotoItem | null`.

## Important behavior

- `photos` is the only identity and navigation-order source.
- Every interactive descendant ID must exist in the collection.
- A descendant becomes inert if its ID is removed while the descendant remains
  rendered.
- Competing custom slide renderers for one ID throw during registration.
- `photos`, `active`, `provider`, `validation`, and `ui` are reactive.
- `lightbox` is setup-time. A group mounted with `:lightbox="false"` stays inert;
  remount with a new `key` to enable it.

## Several albums, one navigation order

```vue
<PhotoGroup :photos="[...landscapes, ...portraits]">
  <PhotoAlbum :photos="landscapes" />
  <PhotoAlbum :photos="portraits" />
</PhotoGroup>
```

Changing the visual order does not change next and previous navigation. Change
the group `photos` array to change that order.

[Share one lightbox](/docs/guides/share-one-lightbox) explains the setup and
why the collection is explicit.

## Class targets and reactivity

`ui` keys: `root`.
Collection data and class targets can change after mount.
