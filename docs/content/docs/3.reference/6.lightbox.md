`Lightbox` renders the ready-made viewer UI. It consumes a lightbox provider; it
does not create a collection by itself.

## Minimal usage

Wrap `Lightbox` and pass the wrapper to a ready-made collection component:

```vue [app/components/AppLightbox.vue]
<script setup lang="ts">
import { Lightbox } from '@lupinum/nuxt-photo/app'
</script>

<template>
  <Lightbox />
</template>
```

```vue [app/pages/gallery.vue]
<script setup lang="ts">
import AppLightbox from '~/components/AppLightbox.vue'
</script>

<template>
  <PhotoAlbum :photos="photos" :lightbox="{ component: AppLightbox }" />
</template>
```

The album creates the provider before it renders `AppLightbox`.

## Props

`Lightbox` has no public props. Configure the collection component, provider,
global defaults, and slots instead.

## Events

`Lightbox` emits no public events. Use `useLightbox()` or the collection
controller when application code needs open and close state.

## Slots

| Slot      | Props                                                                                                           | Purpose                                     |
| --------- | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| `counter` | `{ activeIndex, count }`                                                                                        | Replace the slide counter.                  |
| `actions` | `{ activeIndex, activePhoto, count, prev, next, close, toggleZoom, isZoomedIn, zoomAllowed, controlsDisabled }` | Replace the top action controls.            |
| `caption` | `{ photo, index }`                                                                                              | Replace the active photo caption.           |
| `tools`   | `{ photo, index }`                                                                                              | Add content before built-in tools and Zoom. |
| `slide`   | `{ photo, index, width, height }`                                                                               | Replace active slide image content.         |

## Exposed template-ref API

`Lightbox` exposes no public template-ref API. All ready-made components
expose `GalleryHandle`.

## Important behavior

- `Lightbox` must render inside a provider: a ready-made component's
  `lightbox` option or `LightboxProvider`. Elsewhere it
  throws an error that says so.
- A slot replaces only the visible markup of its region. Keep native buttons,
  accessible names, disabled states, and visible focus in your markup.
- Labels come from `nuxtPhoto.labels`; see
  [Configuration and labels](/docs/reference/configuration-and-labels#labels).

## Focus and page isolation

The lightbox is a modal dialog named "Photo viewer". While it is open, it
takes keyboard input, moves focus into the viewer, and makes the page behind it
inert. Closing returns focus to the thumbnail of the photo you were viewing.
Only one lightbox is open at a time.

## Opening animation

The lightbox grows the photo out of its thumbnail and shrinks it back on close.
This is a FLIP animation (First, Last, Invert, Play): it measures the
thumbnail and the final slide, then animates between them. Set it with the
`lightbox.transition` option.

| Mode   | Behavior                                                            |
| ------ | ------------------------------------------------------------------- |
| `auto` | Uses FLIP when enough of the thumbnail is visible; otherwise fades. |
| `flip` | Always tries to animate from the thumbnail.                         |
| `fade` | Cross-fades without moving from the thumbnail.                      |
| `none` | Opens without a transition.                                         |

`auto` is the default. `autoThreshold` defaults to `0.55`, which means at least
55 percent of the thumbnail must be visible. The visible part must also be at
least 80 pixels wide and high; smaller thumbnails fade. Raise the threshold when movement
from partly hidden thumbnails is distracting.

Closing animates to the thumbnail of the photo you were viewing when it closed.
It fades when that thumbnail is gone or outside the viewport.

## Changing photos

The `lightbox.navigation` option sets how the lightbox moves from one photo to the next.

| Mode        | Behavior                                                            |
| ----------- | ------------------------------------------------------------------- |
| `slide`     | Photos sit on a strip. A swipe drags the strip with the finger.     |
| `fade`      | The current photo fades out, then the next photo fades in.          |
| `crossfade` | The next photo fades in over the current one; the room never shows. |

`slide` is the default. In `fade` and `crossfade`, a swipe still works: the
photo follows the finger a little and fades with the distance. A long or fast
swipe changes the photo, and a short one settles back.

## Keyboard controls

| Key          | Action                                                        |
| ------------ | ------------------------------------------------------------- |
| `Escape`     | Close and focus the thumbnail of the photo you were viewing.  |
| `ArrowRight` | Show the next photo, or pan when the current image is zoomed. |
| `ArrowLeft`  | Show the previous photo, or pan when zoomed.                  |
| `Home`       | Show the first photo.                                         |
| `End`        | Show the last photo.                                          |
| `z`          | Zoom to the photo's real pixels, or back to fit.              |
| `Tab`        | Move through the lightbox controls, and show hidden controls. |

Right-to-left direction reverses directional navigation. Text fields, text
areas, selects, and editable content keep their keyboard input. Other controls
receive the event before the lightbox. Call `event.preventDefault()` from a
custom control when it must suppress a built-in shortcut such as Escape, an
arrow key, Home, End, or `z`.

## Pointer gestures

A click or tap beside the photo closes the lightbox.

| Input                | On the photo                     | While zoomed       |
| -------------------- | -------------------------------- | ------------------ |
| Mouse click          | Zoom to the photo's real pixels. | Zoom back to fit.  |
| Touch tap            | Show or hide the controls.       | Show or hide them. |
| Touch double tap     | Zoom to the tapped point.        | Zoom back to fit.  |
| Drag                 | Show the previous or next photo. | Move the photo.    |
| Vertical touch drag  | Close the lightbox.              | Move the photo.    |
| Pinch or mouse wheel | Change the zoom where supported. | Change the zoom.   |

The real-pixel ratio is the smaller of `photo.width / frameWidth` and
`photo.height / frameHeight`, using the fitted frame's CSS pixels. Click,
double tap, and `z` use that ratio capped at `4`, or `minZoom` if it is larger.
This same value is the maximum zoom. `minZoom` can therefore enlarge a photo
beyond its intrinsic pixels. Its default is `1.5`.
Pan bounds keep a photo that is larger than the gesture area against that
area's edges; a smaller photo stays centered instead of panning freely.

Hidden controls leave the `Tab` order. A mouse movement or the `Tab` key shows
them again.

## Reduced motion

Nuxt Photo observes `prefers-reduced-motion`. It replaces movement-heavy
transitions with a short fade and reacts when the preference changes. Custom
lightbox content must provide its own reduced-motion treatment.

Use native buttons for custom controls and keep visible focus styles. The
[primitives guide](/docs/guides/build-a-lightbox-from-primitives) has an
accessibility checklist for custom markup.

## Tools, history, and URLs

`lightbox.tools` defaults to `[]`. `download` links to `photo.src` with the
`download` attribute. Cross-origin links open in a new tab with `rel="noopener"`.
`share` uses the Web Share API with `title: photo.alt ?? photo.caption`. Its
URL is the deep link when enabled, otherwise the current page URL. It appears
only when the API is supported.
`fullscreen` toggles the Fullscreen API on the lightbox root and appears only
when it is supported. The `tools` slot receives `photo: PhotoItem | null` and
`index: number`. Replacing `actions` also replaces the tools area.

`lightbox.history` defaults to `true`. Opening pushes a browser history entry;
Back closes the viewer. Closing a viewer opened from its own entry goes back.
`deepLink` defaults to `false`; `true` uses the `photo` query parameter, and a
string sets another parameter name. The value is the photo ID. Navigation
updates the URL without a route navigation. An initial matching ID opens
without the opening animation. An unknown ID does not open the viewer.
Closing an initial deep link removes the parameter with `replaceState`.

The built-in viewer mounts image slides within three positions in each direction around the active
photo, wrapping around the collection, plus any slide still leaving. Other positions keep track spacers.

The slot props use zero-based indexes. `actions.activePhoto` and
`caption.photo` can be `null`; `slide.photo` is a `PhotoItem` and `width` and
`height` are the fitted frame size in pixels. `counter.count` is the collection
length. Action callbacks are `prev(): void`, `next(): void`,
`close(): Promise<void>`, and `toggleZoom(): void`. Its three control-state
fields are booleans. `Lightbox` has no `ui` prop.
