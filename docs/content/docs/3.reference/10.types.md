## `PhotoItem<TMeta>`

```ts
interface PhotoItem<TMeta extends object = Readonly<Record<string, unknown>>> {
  readonly id: string
  readonly src: string
  readonly width: number
  readonly height: number
  readonly thumbSrc?: string
  readonly placeholderSrc?: string
  readonly alt?: string
  readonly caption?: string
  readonly description?: string
  readonly srcset?: string
  readonly meta?: Readonly<TMeta>
}
```

The data shape every component accepts. `id`, `src`, `width`, `height` are required.

- [Use your own photos](/docs/guides/use-your-photos)

## `InvalidPhotoPolicy`

```ts
type InvalidPhotoPolicy = 'throw' | 'drop'
```

Controls how collection components handle invalid photo data.

- `'throw'`: stop with a `PhotoValidationError`. This is the default.
- `'drop'`: skip invalid photos, render the valid ones, and emit `invalidPhotos`.
  Use `drop` only when the app explicitly accepts missing photos for dynamic
  content. Data behavior is identical in development and production.

## `InvalidPhotosEvent`

```ts
type InvalidPhotosEvent = {
  readonly owner: string
  readonly issues: readonly PhotoValidationIssue[]
  readonly rawPhotos: readonly unknown[]
}
```

Emitted as `invalidPhotos` when a collection component receives invalid photo
data while `validation="drop"` is set.

## `PhotoValidationIssue`

```ts
type PhotoValidationIssue = {
  readonly code: PhotoValidationIssueCode
  readonly owner: string // the component, for example 'PhotoAlbum'
  readonly index: number // position in the photos array you passed
  readonly id?: string
  readonly message: string
}

type PhotoValidationIssueCode =
  | 'missing-id'
  | 'missing-src'
  | 'invalid-width'
  | 'invalid-height'
  | 'duplicate-id'
  | 'invalid-item'
  | 'invalid-optional-field'
  | 'invalid-meta'
```

Use `code` to count or report problems by kind; `message` is for people.

## Lightbox controllers and handles

`PhotoAlbum` and `PhotoGroup` expose the small `LightboxHandle` through template
refs:

```ts
interface LightboxHandle {
  open(index?: number): Promise<void>
  openById(id: string): Promise<void>
  close(): Promise<void>
  readonly isOpen: boolean
}
```

`LightboxController` is returned by `useLightbox()` and `provideLightbox()`. It
exposes reactive photos, active photo state, navigation, close, and zoom
controls. `LightboxProviderController` is returned by `provideLightbox()` and
adds what a custom thumbnail layout needs for the opening animation:

```ts
interface LightboxProviderController extends LightboxController {
  /** Index of the thumbnail the animation currently stands in for, or null. */
  readonly hiddenThumbnailIndex: Readonly<Ref<number | null>>
  /** Returns a template ref callback that registers the thumbnail at `index`. */
  setThumbnailRef(index: number): (element: Element | ComponentPublicInstance | null) => void
}
```

`PhotoTrigger` uses both for you. Call them yourself only when you render
thumbnails without `PhotoTrigger`.

`LightboxSlideRenderer` is the function type of a custom slide renderer, as
passed through `provideLightbox({ resolveSlide })`:

```ts
type LightboxSlideRenderer = (props: { photo: PhotoItem; index: number }) => VNodeChild
```

## `PhotoLabels` and `PhotoDefaults`

`PhotoLabels` contains every visible and assistive label. `PhotoDefaults`
contains shared lightbox defaults that can be provided through
`PhotoDefaultsKey`:

```ts
interface PhotoDefaults {
  minZoom?: number
  labels?: Partial<PhotoLabels>
}
```

[Configuration and labels](/docs/reference/configuration-and-labels#labels) is the canonical
reference for label keys and defaults.

## `PhotoCarouselAutoplayOptions`

```ts
interface PhotoCarouselAutoplayOptions {
  readonly delayMs?: number
  readonly stopOnInteraction?: boolean
  readonly stopOnMouseEnter?: boolean
}
```

`delayMs` defaults to `4000`. `stopOnInteraction` defaults to `true`.
`stopOnMouseEnter` defaults to `false`. The delay must be greater than zero.

## `ResponsivePhotoSizes`

```ts
type ResponsivePhotoSizes = {
  size: string

}
```

Use this layout-aware form for rows albums. `PhotoAlbum.sizes` also accepts a
native HTML `sizes` string.

## `PhotoValidationError`

A runtime-exported error class with readonly `owner` and `issues` fields:

```ts
import { PhotoValidationError } from '@lupinum/nuxt-photo/app'

if (error instanceof PhotoValidationError) {
  console.error(error.owner, error.issues)
}
```

## `AlbumLayout`

Discriminated union of the three layout variants.

```ts
type RowsAlbumLayout = {
  type: 'rows'
  targetRowHeight?: ResponsiveParameter<number>
}

type ColumnsAlbumLayout = {
  type: 'columns'
  columns?: ResponsiveParameter<number>
}

type MasonryAlbumLayout = {
  type: 'masonry'
  columns?: ResponsiveParameter<number>
}

type AlbumLayout = RowsAlbumLayout | ColumnsAlbumLayout | MasonryAlbumLayout
```

TypeScript enforces that `targetRowHeight` is only valid on `rows` and `columns` is only valid on `columns`/`masonry`.

## `ImageAdapter`

```ts
type ImageAdapter = (photo: PhotoItem, context: ImageContext) => ImageSource
```

The contract for routing images through a provider. Receives a photo and the render context, returns the `<img>`-ready source data.

## `ImageSource`

```ts
type ImageSource = {
  src: string
  placeholderSrc?: string
  srcset?: string
  sizes?: string
  width?: number
  height?: number
}
```

The return type of `ImageAdapter`. Nuxt Photo copies these attributes onto the rendered `<img>`.

## `ImageContext`

```ts
type ImageContext = 'thumb' | 'slide'
```

Tells an adapter whether the image is being rendered as:

- `'thumb'`: a thumbnail in an album, group, or carousel.
- `'slide'`: a photo in the lightbox, usually close to screen width.

## `TransitionMode`

```ts
type TransitionMode = 'flip' | 'fade' | 'auto' | 'none'
```

How the lightbox opens and closes. `'auto'` (default) animates from the thumbnail when enough of it is visible, and fades otherwise.

- [Opening animation](/docs/reference/lightbox#opening-animation)

## `LightboxTransitionOption`

```ts
type LightboxTransitionOption =
  | TransitionMode
  | {
      mode: TransitionMode
      autoThreshold?: number
    }
```

Either a mode string or an object with a custom `autoThreshold` (the intersection ratio above which `'auto'` uses FLIP). Default `autoThreshold` is `0.55`.

## `LightboxNavigationMode`

```ts
type LightboxNavigationMode = 'slide' | 'fade' | 'crossfade'
```

How the lightbox changes from one photo to the next. `'slide'` (default) moves the photos on a strip that follows the finger. `'fade'` fades the current photo out, then the next one in. `'crossfade'` fades the next photo in over the current one.

- [Changing photos](/docs/reference/lightbox#changing-photos)

## `ResponsiveParameter<T>`

```ts
type ResponsiveParameter<T = number> = T | ((containerWidth: number) => T)
```

A prop value can be static or responsive to the current container width. Build a responsive value with `responsive()`.

- [Responsive layouts](/docs/guides/responsive-layouts)

`ResponsiveResolver<T>` is the function that `responsive()` returns. It takes
the container width and also carries its breakpoints, so the album can snap
measurements to them.

## Module option types

`nuxt.config.ts` and `app.config.ts` are typed automatically. To type your own
helpers, import the option types from the module entry:

```ts
import type { NuxtPhotoAppConfig, NuxtPhotoOptions } from '@lupinum/nuxt-photo'
```
