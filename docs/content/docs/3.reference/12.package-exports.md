title: Package exports
description: The supported import paths for Nuxt (@lupinum/nuxt-photo/app) and plain Vue (@lupinum/vue-photo), and everything each one exports.
---

Use only these package entry points. Source folders and generated files are
not public application imports.

| Entry point | Purpose |
| --- | --- |
| `@lupinum/vue-photo` | Plain Vue components, helpers, and types. |
| `@lupinum/vue-photo/styles.css` | Complete structure and theme CSS. |
| `@lupinum/nuxt-photo` | Nuxt module. |
| `@lupinum/nuxt-photo/app` | Application API, including usePhotoFolder. |

## Vue root runtime exports

```text [Runtime exports]
Lightbox,
LightboxAmbient,
LightboxCaption,
LightboxControls,
LightboxOverlay,
LightboxProvider,
LightboxRoot,
LightboxSlide,
LightboxViewport,
Photo,
PhotoAlbum,
PhotoCarousel,
PhotoGroup,
PhotoImage,
PhotoTrigger,
PhotoValidationError,
createPhoto,
definePhotoProvider,
validatePhotos,
responsive,
useLightbox,
usePhotoLabels
```

These are the complete runtime exports. The [types reference](/docs/reference/types)
lists the complete type-only exports.

```ts [app/main.ts]
import { createPhoto, PhotoAlbum, responsive, type PhotoItem } from '@lupinum/vue-photo'
import '@lupinum/vue-photo/styles.css'
```

## Nuxt module root

The only runtime export is `default`, the Nuxt module. The only type-only
export is `NuxtPhotoOptions`.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@lupinum/nuxt-photo'],
})
```

## Nuxt application exports

`@lupinum/nuxt-photo/app` re-exports every Vue root runtime and type-only
export above, and adds exactly one runtime export: `usePhotoFolder`.
Use this entry point for explicit Nuxt app imports.

```ts [app/utils/gallery.ts]
import { responsive, type PhotoItem } from '@lupinum/nuxt-photo/app'
export const columns = responsive({ 0: 2, 640: 3 })
```

Nuxt registers Photo, PhotoAlbum, PhotoGroup, and PhotoCarousel by default.
Its default auto-imports are useLightbox, usePhotoLabels, usePhotoFolder, and
responsive. Lightbox must be imported explicitly. Lower-level components
are auto-registered only with `components: { primitives: true }`.
