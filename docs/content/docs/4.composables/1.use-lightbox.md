---
title: useLightbox
description: Read lightbox state and drive it from any component.
---

`useLightbox()` is the **consumer** composable. It reads an existing lightbox context provided by a parent `useLightboxProvider()` call or a `<LightboxProvider :photos="...">`.

Use it when you want to open the lightbox from somewhere that isn't a photo thumbnail — a button in the navbar, a list item, a deep-linked URL.

```ts
import { useLightbox } from '@nuxt-photo/vue'
```

## Signature

```ts
function useLightbox(): {
  photos: ComputedRef<readonly PhotoItem[]>
  count: ComputedRef<number>
  activeIndex: ComputedRef<number>
  activePhoto: ComputedRef<PhotoItem | null>
  isOpen: ComputedRef<boolean>
  open: (index?: number) => Promise<void>
  openById: (id: string) => Promise<void>
  close: () => Promise<void>
  next: () => void
  prev: () => void
  toggleZoom: () => void
}
```

## Basic use

```vue
<script setup lang="ts">
import { useLightbox } from '@nuxt-photo/vue'

const lightbox = useLightbox()
</script>

<template>
  <button @click="lightbox.open(0)">Open first photo</button>

  <div v-if="lightbox.isOpen.value">
    Viewing {{ lightbox.activeIndex.value + 1 }} / {{ lightbox.count.value }}
  </div>
</template>
```

Render this component under a parent that provides the lightbox context, such as `<PhotoGroup>`, `<LightboxProvider>`, or a custom component that calls `useLightboxProvider()`. Calling `useLightbox()` in the same component that renders the provider will not work, because Vue injection only flows from parent to child.

## Returned API

### Actions

- `open(index)` — open the lightbox at an index.
- `openById(id)` — find the matching photo by id and open it.
- `close()` — close the lightbox.
- `next()` / `prev()` — navigate between slides.
- `toggleZoom()` — toggle the active slide between fit and zoomed states.

`open` and `close` are async — they resolve when the transition settles. Useful for chaining:

```ts
await lightbox.open(3)
logAnalytics('lightbox_opened', { index: 3 })
```

### Reactive state

- `isOpen` — `true` when the lightbox is open or opening.
- `activeIndex` — current slide index.
- `activePhoto` — the `PhotoItem` at `activeIndex`, or `null`.
- `photos` — the provider's normalized photo list.
- `count` — total photos.

All state values are readonly computed refs; unwrap them in templates as usual
(`lightbox.activeIndex.value`). Invalid open targets reject with `RangeError`.

## Scope: consumer vs provider

`useLightbox` does not create lightbox state. It only consumes a lightbox context that already exists. The convention in Nuxt Photo:

| Where                                     | What to call                                                   |
| ----------------------------------------- | -------------------------------------------------------------- |
| Building a custom lightbox                | `useLightboxProvider` or `<LightboxProvider :photos="photos">` |
| Consuming a lightbox your parent provided | `useLightbox`                                                  |
| Inside a bundled primitive                | Internal context helpers                                       |

## Deep-linking example

```vue
<!-- GalleryWithQuery.vue -->
<script setup lang="ts">
import type { PhotoItem } from '@nuxt-photo/vue'

const photos: PhotoItem[] = [
  { id: 'desert', src: '/photos/desert.jpg', width: 1280, height: 800 },
  { id: 'ocean', src: '/photos/ocean.jpg', width: 960, height: 1200 },
]
</script>

<template>
  <LightboxProvider :photos="photos">
    <DeepLinkController />

    <div class="grid">
      <PhotoTrigger v-for="(p, i) in photos" :key="p.id" :photo="p" :index="i">
        <img :src="p.thumbSrc ?? p.src" :alt="p.alt" />
      </PhotoTrigger>
    </div>
    <Lightbox />
  </LightboxProvider>
</template>
```

```vue
<!-- DeepLinkController.vue -->
<script setup lang="ts">
import { useLightbox } from '@nuxt-photo/vue'

const route = useRoute()
const router = useRouter()
const lightbox = useLightbox()

onMounted(() => {
  const id = route.query.photo
  if (id) lightbox.openById(String(id))
})

// Sync URL with active photo while open
watch([lightbox.isOpen, lightbox.activePhoto], ([open, photo]) => {
  if (open && photo) {
    router.replace({ query: { ...route.query, photo: photo.id } })
  } else {
    router.replace({ query: { ...route.query, photo: undefined } })
  }
})
</script>
```

This example assumes the provider renders the same `photos` collection the URL can reference. Keep those two paths aligned or the query string can point to a photo the lightbox never registered.
